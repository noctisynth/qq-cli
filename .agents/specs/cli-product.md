# 面向 coding agent 的 CLI 产品契约

文档编号：SPEC-004。状态：Active，持续开发，核心模块有离线证据。更新：2026-10-18。
依据：用户 Rust、完整工具、Agent 自动处理及易用/准确/减少 token 要求；关联 SPEC-001、PLAN-001、RFC-0002、RFC-0003、RFC-0004、TASK-002。

## 产品要求

完整交付全部确定范围、可靠性、指引和验收，不能以部分功能或开发快照替代；不表示所有 QQ API、零缺陷或账号安全。
PLAN-001 为公共命令/模型/预算/错误契约，TASK-002 登记差距。

覆盖离线 schema/skill、NapCat 环境/固定安装/多实例、版本兼容证据、联系人/群/会话发现、
私聊/群读取、分页/时间/范围搜索/导出、文本/回复/提及/图片/文件发送、转发读取、
媒体下载/自有缓存、事件及缺口、请求记录与 Codex/OpenCode 闭环。
默认 JSON/流 NDJSON，错误和部分结果可机器理解；权限/时间/条数/字节/落盘预算有界。

## 简化 UX

不公开 profile、managed/external 或预设账号绑定/改绑，外部接入不纳入必需范围。
零实例时在授权范围内自动准备，单候选自动选择，多候选返回 INSTANCE_AMBIGUOUS，--instance 精确选择；
消息引用/游标作用域优先，不能按焦点或最近活跃猜实例。
新实例无需账号，未登录 account=null；登录后输出实际身份。变化返回 ACCOUNT_CHANGED，旧作用域不可复用。
身份核对与去重是内部准确性要求，不让 Agent 维护配置或填冗余字段。
默认只返回任务结果与简短作用域，详细 schema/诊断按需读取。

napcat install/installations/uninstall 管理本地安装；start/instances/stop/restart 管理实例，
remove 注销停止实例，update/rollback 明确切换实例版本。每个对象有不同 ID，一份安装可供多实例使用。
start 默认复用，--new --request-id 明确另开并防串行重试多开；stop 不卸载，uninstall 不关闭 QQ，被运行或停止实例引用的安装不得删除。
remove 不删除 QQ 数据或防重记录，卸载只删除工具拥有的无引用产物，注册与文件变更防并发竞争。
产物先核对私有快照的固定长度/摘要再解包，限制压缩/展开大小、成员数/深度并拒绝不安全路径和链接；机制与预算见 RFC-0003。
安装使用签名所有权清单、确定ID和状态锁；卸载保护已停止实例的引用，持久移除日志后只删除已验证清单成员，中断重试保留未知文件、QQ数据和请求记录。

## 语义与职责要求

以 RFC-0004、PLAN-001 为目标命令面，解析/帮助已迁移，完整领域 schema 和业务仍在实施。
status 汇总实际账号/就绪，doctor 诊断环境/版本/能力，登录恢复使用 napcat start，不另设 self/auth/capabilities 等重复入口。
doctor只读采集，区分安装元数据、精确Framework兼容证据和所选实例API；API成功或静态/Shell报告不能提升为完整兼容。canStart仅受检前置条件，真实元组与实际启动绑定仍须验收。
contact list/get 负责好友和资料，group list/get/members 负责群及成员，conversation list/get 负责最近聊天和会话信息。
conversation list --query 始终仅过滤最近会话，contact/group 过滤各自对象范围，不隐式跨域；已知目标无需先发现/查询详情。
message send 面向新消息，reply <message-ref> 面向引用回复并推导目标，共享防重但不互为别名。
message history/search 只返回查询 JSON；export 独立负责文件、可选检索、检查点/--resume、覆盖保护，stdout 仅文件摘要。
导出为带 type 的 NDJSON，message 行与末尾签名 checkpoint 行在一次原子替换中提交；续写先核对正文摘要与作用域，累计上限64MiB。
schema/skill/request 统一 get，event 单数；转发展开仍 get --expand，消息自带媒体元数据，download 才取内容。
公共数量/截止/续传统一 limit/timeout/cursor，不暴露取页批次/页数/投影 DSL。
普通满页成功不代表完整历史；中断部分页才返回退出码 7，不制造正常分页错误。
成功 JSON 省略空字段/重复 command/日常关联号，保留作用域/范围；失败保留必要恢复信息，不让 Agent 猜测。
无需每次先 schema/doctor/dry-run，真实命令内部检查；不以命令最少为目标；按语义分工，通过默认值和按需发现降低调用成本。

## 边界与验收

使用原版 Framework，不改 NapCat、不 fork、不开发加载器，不用 UI 自动化替代 API，不打包上游。
Windows、NapCat v4.18.38 为证据基线，其他支持需来源和验证；unknown 兼容不能冒充 supported 或默认加载。
不提供 raw action、群管理、自动回复或执行聊天指令；身份发现不自动授予业务权限。
CLI 退出不关 QQ，不自动终止外部 QQ、挤掉账号或重启活跃窗口。
登录挑战/系统授权明确阻塞，安装选择、预检、目录隔离及启动控制面尚待机制验证。
按 PLAN-001 整体验收，包括安装卸载/实例引用、并发、身份切换、防重、历史边界、媒体、事件及两个宿主。
无真实回归证据即未验收，许可和分发问题仍需解决。

## 当前状态与授权

skill list/get 离线提供 discover/read/send/media/events/runtime 任务指引；export 输出独立 Skill 包，拒绝覆盖现有目录，不修改宿主配置。

工程基础 CHECK-008 保留；核心模块、HTTP、部分集合读取、消息引用、历史/搜索/导出、文本/发送内核与持久化写意图的合成验收见 CHECK-013。
status 显式检查切换后的身份并更新观察基线；旧引用/游标仍绑定旧账号，不随之迁移。
未完成业务仍明确失败；未运行真实 CLI 会话，已有原版 API 实验不计 CLI 功能。
当前用户授权持续实施全部已确认功能，完成必要离线验收，按依赖逐项推进；技术机制不能正确落地时记录证据。
不暂存、不提交，不以开发授权推导任意真实启动、私人读取或发送目标。

历史读取仅传输失败可有界缩小批次20→10→5→2，失败尝试计入page_limit且共享总截止，保持原锚点；认证/协议/业务失败不自动重试。backendPages表示历史取页尝试数（含失败）；耗尽不当作历史终点。

媒体本地文件复制的客户端硬上限128MiB；来源根必须由受管实例所有权确定，不能信任后端返回路径即读取任意文件。校验消息可用大小，复制有总截止及SHA-256，私有临时文件不覆盖原子发布；此客户端限制不表示上游支持所有格式或大小。

事件客户端内核限制单帧4MiB、每次最多10000帧和1000条数据事件，输出累计字节与总截止共享配置；心跳/重复不冒充新消息。账号变化先于目标过滤检查，失败后不得继续消费同一流；未知notice只给不支持标记，不透传原始私密对象。

正向WS仅显式端口字面回环ws地址，root或/event路径；拒绝URL凭据、查询参数、fragment、跳转和自动重试，认证仅敏感请求头。握手阶段累计接收32KiB，成功后流总接收64MiB（包含握手）/写64KiB、完整消息/帧4MiB，完整消息或控制帧最多10000个；I/O共享总截止，不继承代理，不使用DNS。

事件编排在连接与重连前后核对原账号，持续观察每5秒复核；最多2次重连、退避250/500ms并受总截止/取消约束。每条NDJSON完整编码换行后flush，输出失败停止读取并关闭本命令socket；截止后summary输出可有1秒有界宽限。普通阻塞Write不能证明截止，进程输出使用容量1队列/逐条确认与截止，失败后不再写；CLI退出不等待阻塞写线程，须以实际阻塞管道测试验证，不将工作线程策略当可复用库的OS写取消。

通知采用白名单字段投影：撤回、好友新增、群成员增减/管理员变更分别携带已确认kind/时间/相关ID/子类型，不透传原始URL或对象。群变更未解析user/operator的0哨兵输出null；好友通知按private目标过滤。未知通知/子类型明确不支持，不猜测含义。

event.watch按NDJSON记录发布responseSchema，启动前单行失败另由preStreamErrorSchema描述，并提供streamProtocol顺序/错误说明；实际输出须通过独立JSON Schema验证。其他命令完整领域schema仍按整体契约验收，不能以事件schema代替。

联系人、群/成员、最近会话读取输出使用独立领域schema，账号/资源ID字符串，成功作用域必需，列表分页完整性和游标相互一致；不输出未声明的后端字段。group get响应必须对应所请求群，最近活动秒时间遵循与消息一致的有效秒范围。

附件准备的逻辑内容指纹包含类型/展示文件名/字节数/SHA-256，不包含源路径或随机暂存路径；显式本地文件先固定私有副本，非空且客户端上限128MiB，不把此上限当作上游容量或格式支持。进入可能异步写阶段前须持久关联副本所有权/请求；未知结果不得自动删除或重试。

保留的附件副本必须有签名request/instance/account所有权，恢复时校验受管目录、签名、长度/摘要及目录清单；拒绝错请求/账号、额外或未知文件。所有权登记不等同已发起写入，后续仍需独立durable pending及作用域/内容一致性检查。

media prune离线维护附件副本，--instance仅过滤所有权。仅有匹配作用域且accepted/rejected的请求、超过24小时的签名副本可清理；pending/unknown、缺失记录和不可信目录保留。删除先持久journal、仅删已核对成员及非递归空目录，支持中断恢复，不操作QQ缓存。

附件根使用1GiB/最多256项客户端硬配额，状态锁内检查及准备，未知文件计入占用但不接管/删除；每项预留至少1KiB所有权标记容量。配额不足明确失败并指引显式media prune，不为腾空间自动删除不确定写结果所需副本。

附件最多image/file合计16项，以内容指纹进入pending后再保留副本，并绑定同一payloadHash；只通过单次send_*承载附件段，不叠加upload_*。内部传输阶段不可观察时明确not_observable/unknown，不等于失败或允许重传；消息接受以最终messageId及身份复核判断。dry-run可有界准备临时副本，不保留副本或建立写意图。

写结果的错误作用域沿用已持久请求绑定，不随当前QQ账号变化迁移；unknown给出request.get与符合该命令输入schema的request_id参数，供Agent离线查证，不授权重发。实际send CLI必须覆盖私聊/群、接受/不确定和原生临时凭据路径；真实协议仍独立验收。

reply完整CLI必须从签名引用推导原实例/账号/会话，存在多个候选时仍按引用选择；显式冲突在读取无关凭据或访问后端前拒绝。假会话覆盖目标复核、附件、接受/unknown及服务离线后的同键/request get，不替代真实协议验收。

send/reply和request get发布领域输出Schema，dry-run、消息接受、附件传输不可观察/unknown分别建模。缓存accepted回执须有有效非零i64/u64消息ID、合法会话及匹配的附件元数据，重试目标不符或回执损坏明确失败，不重新发起写入。持久请求元数据必须有合法作用域、请求键、操作标识和摘要。

message get/history/search与event共用消息段及递归转发输出定义；history/search分别描述成功、含正文的PARTIAL_RESULT与无正文错误。未完成页必须含h1续传引用，完成页无续传且给出backend_end/range_satisfied，coverage固定backend_accessible，不宣称全量QQ归档。部分结果不能省略错误或伪装complete=true。

总截止由命令入口一次确定，实例/凭据准备、引用恢复和领域操作共用，不得在阶段切换时重新起算。可取消边界发现过期即不进入下一阶段；查询已有结果遵循部分结果契约。不把此协作检查解释为可以强制中断所有同步系统调用。

普通业务、状态API探测、事件及doctor的API层统一从可信签名运行记录恢复服务身份，核对所选run/安装摘要/端点及完整进程/Job；缺失或损坏不得回退到普通HTTP/WS，非标准凭据键也不构成例外。已有完全匹配的幂等回执仍能离线返回，不以当前进程/凭据不可用授权重发。独立低层协议测试不替代该CLI门禁；合成服务成功不证明原版启动、兼容或真实账号安全。

托管配置模板只面向固定审核版本与将要创建的私有实例，不覆盖任何已有QQ/NapCat配置。预登录生成通用onebot11.json、webui.json及napcat.json，不生成预设账号文件；HTTP/WS/管理面使用三个不同的非特权IPv4回环端口。业务API与事件共享专用随机密钥，管理令牌与JWT签名密钥分别独立生成，不放入普通注册表或默认输出；JSON配置由私有目录/ACL和所有权事务承载。模板启用array消息、自发事件及文件字节能力，禁用反向上报/插件/CORS/调试和文件日志，不改变未核实的Hook/Bypass参数。管理端口自动回退不能当已发现，发出管理凭据前必须核对实际监听所有权；上游日志不直接继承到CLI。

运行配置准备事务仅接受同一登记实例/run、preparing或prepared阶段、未记录进程/账号且端点一致的计划。先持久签名所有权日志，再向一个受保护凭据条目保存整组秘密，业务原始token条目可从该组恢复；未知既存条目不得接管。配置进入日志预先认领的固定暂存目录，已有成员仅可为准确预期内容的子集，缺失成员可补齐，额外/修改/链接拒绝且不覆盖。完整目录在Windows以不覆盖语义发布后再提交prepared阶段；重试复用同一秘密。内部r1所有权引用不向公共命令开放。此处不授权进程启动：生命周期必须先持久starting意图再spawn，准备函数拒绝后续运行阶段，不能用目录存在推断进程未启动。

准备中的未完成暂存文件仅允许追加与原预期一致的缺失后缀，不能改写任何已存在字节；完整已发布文件必须准确匹配。准备态不能进入业务身份探测或事件连接，status只报告未验证的登记阶段和account=null，不把计划端口当真实API。已有写意图的离线结果查证仍按原契约保留，不为读取旧结果发新请求。

图片来源定位契约：签名媒体引用记录原消息段位置及可用来源身份摘要，不记录URL/rkey；下载前按完整原消息身份及同位置/类型/ID/已知名称和大小复核。仅允许固定产物所生成的三种HTTPS主机及路径形状：gchat.qpic.cn、multimedia.nt.qq.com.cn的图片资源，gxh.vip.qq.com的商城表情资源；查询只接受已确认字段。资源身份包含主机/路径/资源字段，rkey可变化但不参与持久摘要。旧引用无位置时仅可接受唯一匹配，不以文件名首个匹配猜测。来源内核和HTTPS编排已有定向合成证据；真实媒体验收独立进行。

图片HTTPS适配目标：只使用新鲜原消息对应元素的受检URL及来源摘要，独立客户端进行证书/主机名验证，不继承API认证、代理或Cookie，不重定向、不重试、不请求第三方rkey服务。响应必须200，拒绝声明的非图片/非通用字节类型及压缩正文，长度和流均限制128MiB，沿用总截止和不覆盖原子发布；最终身份守卫失败不发布。错误不输出URL、查询、证书或底层网络异常。仅路径校验或出现字节不足以开放此能力，需隔离TLS假服务和编排验收。

媒体内容须在新鲜引用/身份检查后进入有界字节落盘，标准base64严格校验，解码≤128MiB并核对可用大小/哈希；身份守卫失败不发布目标文件。NAPCAT_WORKDIR/cache不能自动授权QQ内核返回的下载路径；字节提供和配置机制见RFC-0003待决项，不全局放宽普通JSON预算。

媒体字节传输为get_file/get_image单独限制编码正文与元数据预算，普通API仍最多4MiB；不读取该响应的任意file路径或跟随url。图片只使用新鲜get_msg对应元素恢复的受检HTTPS来源，不经过文件名缓存。downloadable表示可尝试受作用域保护的解析，不保证源仍有效；历史缺失URL或仅含本地路径时可通过新鲜消息恢复来源，不直接读取该路径。已有不受支持网络URL不广告为可下载；无法恢复可靠来源时明确MEDIA_BINDING_UNVERIFIED。独立file_id进入条件字节路径，开关未启用返回MEDIA_BYTES_UNAVAILABLE，不伪造成功或自动修改外部实例配置。
