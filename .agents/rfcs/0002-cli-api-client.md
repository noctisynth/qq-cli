# 面向 coding agent 的 QQ CLI 需求

文档编号：RFC-0002。状态：Accepted。更新：2026-10-24。
技术方案：SPEC-001、PLAN-001、SPEC-004、SPEC-007。实施与验收：TASK-002。

## 问题与目标

Agent 需要以稳定、低调用成本、可机器判定的方式完成个人 QQ 任务，而用户继续使用官方窗口。
采用用户指定的 Rust CLI；Agent 与用户共用同一会话，后台业务不抢鼠标、键盘或焦点，CLI 退出不关闭 QQ。
不依赖 LiteLoader、不修改或 fork NapCat，不以独立机器人身份或第二个会话冒充共享会话。

## 需求范围

- 离线 schema/skill 自省；帮助、默认值、错误和下一步适合 coding agent 按需使用。
- 环境固定版本安装、多实例及显式维护；自动选择和职责边界见 RFC-0003/0004。
- 好友、群/成员、最近会话的发现和资料读取，保持各自查询范围。
- 私聊/群消息读取、分页历史、范围搜索、导出及续写、受限合并转发展开。
- 文本、引用回复、群提及、图片与文件发送；请求防重及未知结果查询。
- 媒体下载和只清理工具自有缓存；有界事件流、缺口说明及恢复。
- 多账号作用域隔离；Codex/OpenCode 任务发现、歧义处理、读取、发送及未知结果处置的闭环。

## 取舍与非目标

通过 JSON/NDJSON、合理默认值、消息引用和按需帮助降低成本，不强制每次先 doctor/schema/dry-run。
群管理及受检直接API按用户2026-10-27需求纳入RFC-0009，替代旧raw/group排除边界；不暴露profile/managed/external、公开绑定/改绑、QQ密码、营销或默认自动回复。
不通过 UI 自动化替代业务 API，不把所有 QQ 功能、无限历史、永久兼容、免封或零缺陷作为承诺。
外部端点接入没有已确认需求。平台扩展不自动扩大权限或功能范围。

## 验收要求

完整范围内的功能、可靠性、用户文档和 Agent 指引齐备才算完整交付；发布版本或部分原型不能替代。
公共命令、实际输出、Schema 和指引一致；未知/部分结果显式可判定，副作用结果不明时不盲重试。
真实验证应区分平台/版本、目标和操作范围；共享窗口、账号一致、焦点、恢复及完整性分别取证。
需求采纳与单次真实会话操作授权分开；当前差距由TASK-002、macOS专题TASK-006和必要能力专题TASK-007分别维护。

范围内能力不能以 NOT_IMPLEMENTED 占位计为完成；完整交付须通过 TASK-002 的整体验收。
