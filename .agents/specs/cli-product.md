# 面向 coding agent 的 CLI 产品契约

文档编号：SPEC-004。状态：Active，设计已扩展，业务待实现。更新：2026-10-17。
依据：用户要求 Rust、coding agent 和完整工具交付；关联 SPEC-001、PLAN-001、RFC-0002、TASK-002。

## 产品要求

交付是完整工具，不能以部分命令、开发快照或占位返回替代。任务按依赖推进，不代表拆分产品验收。
完整指已确定范围的能力、可靠性、指引和验证闭环，不表示全部 QQ API、零缺陷或账号安全保证。
PLAN-001 定义公共命令、模型、预算、错误及交付契约，TASK-002 登记差距。

必须覆盖：离线 schema/指引、显式多账号 profile、预检和能力证据、联系人/群/会话发现、
私聊/群消息读取、分页/时间过滤/范围搜索/导出、文本/回复/提及/图片/文件发送、
转发读取、显式媒体下载和自有缓存、实时事件和缺口、发送状态查询、Codex/OpenCode 使用验收。
名称歧义不自动选人；绑定期望账号；写入需请求键和持久防重，未知结果不重发。
普通 JSON 和流 NDJSON 稳定，不随 TTY 变化；错误、部分结果、覆盖范围与下一步可机器理解。
读写有权限、时间、条数、字节和落盘预算，不无限扫描或自动下载。

CLI 增加 Agent 托管运行环境，自动准备配置、凭据、端点、原版启动及有界恢复，兼容 external profile。
复用原版 Framework，不修改 NapCat、不 fork、不开发加载器，不用窗口自动化替代 API。
有效登录态下无需用户手工运维；QQ 身份确认、系统授权及运行冲突返回结构化阻塞，不承诺绕过或永远零介入。
不得自动终止外部 QQ、挤掉已有账号会话或重启用户活跃窗口；CLI 退出不关 QQ。具体机制见 RFC-0003。
不提供任意 raw action、群管理、自动回复或自动执行聊天指令，不打包上游。
Windows 和 NapCat v4.18.38 为基线，其他支持需独立证据。

## 验收

执行 PLAN-001 完整交付门槛。候选接口先固定来源及详细契约，再合成测试与明确授权的有界实验。
源码存在不等于运行验证，能力不足登记阻塞并解决，不静默缩减范围。
范围内无占位，覆盖身份隔离、防重、历史边界、媒体安全、事件缺口与两个 Agent 宿主闭环。
无真实回归证据即未验收；许可及分发问题需解决，不承诺全量 QQ 历史、长期兼容或账号安全。
