# 产品基线

文档编号：SPEC-001。状态：Active。更新：2026-10-17。
依据：用户在项目建立前的需求澄清和本次初始化指令。

## 已确认目标

- 用户正常使用官方 QQ 窗口时，Agent 仍可后台调用，不抢占鼠标、键盘或输入焦点。
- 用户和 Agent 使用同一个个人账号会话；不通过创建独立官方机器人身份替代。
- 尽可能复用本机 QQ 安装；不依赖 LiteLoaderQQNT。
- 优先评估原版 NapCat 产物自带的原生入口，自有加载器为备选；本轮不 fork。
- 使用 Rust 提供适合本地 Agent 的 CLI；首版命令/API 方案见 PLAN-001、SPEC-004，已选技术方向见 RFC-0002。

## 本轮授权范围

初始化、固定审计、来源追溯及有界运行/消息实验已完成，证据见 CHECK-002 至 CHECK-006。
当前用户要求完成 CLI M0：Rust/Cargo 工程、离线命令骨架、版本来源迁移与离线验证后提交。
允许安装工具链/依赖并实施 M0，不含后端功能、新增 QQ 操作、发信、fork、远端或推送。
原始实验材料、私人配置与上游源码/二进制继续留在忽略目录；过去单次消息授权不扩展为自动回归。

## 决策边界

用户此前因风险排除注入式 Framework，后续要求研究不依赖 LiteLoader 的独立加载路径。
后续的明确实验授权已用于 CHECK-005、CHECK-006，不能推导为用户接受所有 Hook 机制或任意后续消息操作。
技术可行性与协议、账号风险分别记录；更换加载器不会自动消除风险。

## 后续验收方向

在明确实验范围后验证：官方窗口保留、仅一个目标会话、只读接口工作、用户输入焦点不变、
双方消息事件一致、退出和重连行为可控。真实发信验证需具备明确目标和内容。
已有部分实验通过，不等于完整验收；CLI 首版独立测试要求见 SPEC-004、TASK-002，源码推断不替代运行验证。
