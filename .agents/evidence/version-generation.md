# 版本代次与回滚引用

文档编号：CHECK-024。状态：元数据有界离线验收。更新：2026-10-19。
关联：SPEC-004、RFC-0003、TASK-002、CHECK-022、CHECK-023。

版本切换的前置缺口：原g1仅允许源实例与目标安装相同，卸载只核对当前安装引用。直接修改安装ID会失去原停止证明的安装绑定，也会使旧包在仍需回滚时变成可卸载对象。因此扩展g1的schema2，显式保留sourceInstallation、installation及rollbackInstallation，旧schema1只允许同安装且没有扩展字段；相同ID不能对应不同快照，回滚不能指向当前安装。

跨安装元数据核对原安装的p1完成证明，目标安装按单独快照生成n1与新run。实例ID稳定、账号/进程观察清空，既有安装记录不变，不复制旧配置、凭据或运行目录。普通同安装新代次继承最近不同安装；再次版本切换将本次原安装设为回滚目标，不无界扫描祖先。Inputs的新入口仍在状态事务内重新核对目标安装/QQ/精确兼容，调用方须持生命周期锁；公开版本切换编排尚未接入。

卸载在现有状态事务中读取当前实例的签名来源与原run已认领目标，保护回滚包及g1已写而n1/登记尚未完成的目标包。每实例固定次数读取，不扫描全部历史；损坏的已知来源失败关闭，不改写或补建签名权威。当前安装仍直接保护，注销实例后的历史记录保留不自动成为永久安装引用。

15项原创代次测试通过，包含5项新场景：跨安装保留源停止证明和稳定实例、同来源重复复用；普通新代次保留回滚引用并验证回滚后的反向目标；修改原安装摘要不能借目标证明；扩展记录伪装旧格式或回滚指向当前安装拒绝；用Windows只读共享句柄阻止登记发布，目标卸载仍返回INSTALLATION_IN_USE，释放后复用原计划。此处均为合成安装快照与预启动取消证明，不读取QQ，不启动任何进程，不构成真实包或API验收。

首轮完整回归在库测试阶段失败：83项通过，default_start的稳定默认键及四线程唯一键测试出现DEADLINE/STATE_BUSY。原3秒截止未改，未放宽锁；随后独立运行该模块3项全部通过（0.21秒），原因尚未确定，不能据此归因于资源竞争。另有15项代次定向通过。失败日志留忽略目录，完整回归仍需复核后才可提交阶段完成。

后续在无并行构建时重跑完整回归，280项全部通过，其中85项库测试通过；再单独完成Release构建。fmt/全目标clippy、架构、201文件源码包和Semifold配置/发布计划检查通过，不消费changeset。首轮失败不删除、不以第二轮通过证明根因。版本元数据单列完成子项后业务66/99、运行环境26/35、待完成33；完整更新/回滚任务不勾选。

当前审核目录仍仅固定一个真实版本，运行配置和准备也使用固定目录；本内核不自动信任第二个版本，不意味着update/rollback可用。真实多版本来源/摘要、配置迁移、完整启动与恢复、共享安装/注销竞争、实际QQ兼容及窗口均仍待验收。
