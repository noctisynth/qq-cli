# Rust 模块职责与可维护性整改

文档编号：RFC-0005。状态：Accepted，按用户要求优先整改。更新：2026-10-19。
关联：GOV-001、DESIGN-001、SPEC-004、TASK-002、TASK-003。

## 问题与决定

现有根模块平铺，应用入口混合安装/启动、引用选择、凭据、状态、消息和订阅；启动内核承担CLI输出。按文件拆分未形成可理解的职责边界，不满足模块化维护要求。在质量整改验收前不新增产品功能；既有未提交登录协议研究保留为静态证据，不继续控制实现。

采用单crate的明确分组：core放基础模型/错误/预算/输出；cli放解析、语义校验、schema和Agent指引；storage放本地配置/状态/凭据/签名引用；requests放持久请求键、意图和查询；messaging放读取、发送、历史、事件及附件/媒体子域；napcat拆安装、兼容与运行生命周期；native隔离宿主/进程/Win32 Job；transport放OneBot及受检HTTP/WS；app负责用例组合。

不以根层兼容re-export掩盖迁移，源码和测试使用规范路径。app只公开执行入口与测试所需明确用例；其内部按启动、状态、消息、订阅、实例/引用选择和管理路由拆分。生命周期内核不负责展示AUTH_REQUIRED或构造CLI响应。继续复用已有Session/传输/状态锁契约，不新增通用服务容器、虚假trait或多crate分发负担。

大文件中的单元测试移到所属模块的测试文件，保持模块私有访问和原测试内容；嵌入资源路径与独立进程测试过滤路径随迁移显式更新。unsafe仍仅允许原Win32 Job边界，不能扩大到整个native模块。

重构保持命令、参数、输出、权限、离线/凭据顺序及防重语义；发现实际行为调整另行记录并验证。目录调整只是基础，还须审查应用层是否仍有业务/原生实现混杂、重复启动结果构造和悬挂旧引用。

验收见TASK-003：模块职责可定位、依赖入口可读、旧路径无残留、关键大模块完成职责拆解，既有完整离线测试、fmt/clippy、打包和架构检查通过。未满足前不恢复新增功能；不以一次搬文件或测试通过宣称质量问题已全部解决。
