# Framework 接入与验证技术方案

文档编号：SPEC-003。状态：Active。更新：2026-10-24。
需求：RFC-0002/0003/0008。来源：FACT-001 至 FACT-005。平台细节：SPEC-006/008。

## 装配协议

固定完整 NapCat 包、QQ 版本与受检文件摘要，不混装或自动替换产物；配置、日志与安装文件分离。
Windows 调用原版原生加载入口；macOS 使用专用副本和 SPEC-008 的外部适配。
官方 QQ 继续原始启动链并拥有实际会话；将其 session/loginService 转交原版 Framework。
不同时调用 NCoreInitShell，不创建另一会话补偿失败，不附加或接管无关的现存 QQ。

适配必须保留原方法 receiver、参数、返回和异常，以及原回调语义。
一个初始会话只初始化一次 Framework；就绪来自真实通知，不能伪造通知或仅凭函数返回判定成功。
进程创建、控制端点、QQ 登录、会话就绪、OneBot 身份/API 是不同状态，不互相代替。

## 观察和控制

发现/校验 → 启动 → 等待会话 → API 可用；失败显式报告，断线变为不可用，不盲重启或重复发信。
CLI 退出不自动结束 QQ；显式 stop 的所有权和副作用按 SPEC-006，不能宣称热卸载或优雅登出。
业务和管理面只回环监听并分别认证；管理路由内部白名单，不暴露任意 WebUI/插件/登录接口。
上游日志可能含秘密，不直接继承为 CLI 输出；真实账号/聊天和凭据不进入公开证据。

## 验证设计

| 层次 | 必须验证 | 不能推导 |
|---|---|---|
| 产物 | 来源、完整摘要、实际导出、架构和加载条件 | 可运行、适用许可已解决 |
| 离线适配 | 原方法转发、时序、一次初始化、失败和隐私反例 | 真实 QQ ABI/账号安全 |
| 启动/GUI | 官方入口继续、窗口正常、实际进程与端点归属 | 已登录或全部功能兼容 |
| 真实会话 | 原初始化身份与 OneBot 身份对应、在线、限定 API 结果 | 全量历史、其它版本或长期稳定性 |
| 生命周期 | 明确所有权、退出、重连/恢复、数据保全 | 所有故障已覆盖 |

每次实验固定版本、授权范围、退出/恢复方式和真实结果，记录 CHECK；失败保留原观察，后续证据限定替代范围。
功能、上游生成链/维护信息、许可适用性及账号风险分别记录。未确认许可只按 FACT-002 作审计事项，
不设置技术 canStart 硬阻断；仍保留完整性、兼容、所有权和操作授权检查。
