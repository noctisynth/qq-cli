# Rust 模块职责与可维护性

文档编号：RFC-0005。状态：Accepted。更新：2026-10-24。
技术方案：DESIGN-002、SPEC-001。完成证据与清单：CHECK-017、TASK-003。

## 问题与目标

根模块平铺、应用入口混合多个职责、启动内核承担 CLI 展示，妨碍定位和维护。
要求按职责形成可理解的模块边界，而不是只拆文件或增加目录。

## 要求与取舍

应用层组合用例；领域内核不构造 CLI 响应。平台 unsafe 权限只给明确原生能力边界。
保持命令、参数、输出、授权顺序、离线行为、凭据与防重语义；实际行为变化单独设计和验证。
不增加掩盖耦合的根层兼容别名、虚假 trait、通用服务容器或无必要多 crate 分发。
测试按所属模块组织，迁移保留语义和资源引用，结构门禁阻止反向依赖及权限扩大。

## 验收

职责可定位、依赖入口明确、旧路径无残留，关键模块完成拆分并通过适用回归、构建及包范围检查。
历史整改已验收；此需求继续约束新增平台实现，不意味着所有未来维护问题已消除。
