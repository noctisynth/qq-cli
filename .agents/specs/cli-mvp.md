# CLI 首版实施基线

文档编号：SPEC-004。状态：Active 实施计划，未实现。更新：2026-10-17。
依据：用户本轮要求、SPEC-001、CHECK-005、CHECK-006。用户可读方案为 PLAN-001。

## 本轮范围

基于现有 NapCat OneBot HTTP API 完善 CLI 技术方案和最小实施清单，暂不修改 NapCat。
本轮只写文档，不安装运行依赖、不写 CLI 产品代码、不改实验实例配置、不发消息或扩展历史读取。
过去两次运行实验只提供接口和短时共存证据，不能替代新 CLI 测试。

## 最小交付

单次命令进程，连接用户已经启动的实例；首版支持 doctor、status、self、message get/history/send。
私聊文本为唯一发送类型；目标必须显式给定，消息命令执行前核对 expectedAccount、在线和固定上游版本。
始终 JSON 业务输出、稳定退出码、脱敏错误、字符串标识；stdout/stderr 契约及资源上限以 PLAN-001 为准。
发送需要调用方 request-id、本地跨进程防重记录，未知结果不自动重发，成功只表示上游接受。
CLI 不接入 WebUI 管理接口，不执行 NapCat/QQ 启停、登录、注入、更新，不暴露任意 action。
不实现群聊、媒体、联系人遍历、实时事件或常驻代理；不修改或随包分发上游源码和二进制。

用户明确采用 Rust，Cargo 工程与依赖路线见 RFC-0002；package.json 此时仍只有遗留版本元数据，不能写成工具链已建立。
产品目录按 PLAN-001 的职责拆分即可，不预建没有首版用例的模块。

## 必须通过的验收

- 配置缺失、未知参数、非回环 endpoint、缺少鉴权或文本输入冲突，在发请求前失败。
- 错账号或离线时不读取消息或发信；上游版本/响应不兼容不伪装为成功。
- HTTP 200 的失败 envelope、非 JSON、截断/超限响应及无法无损解析的数字标识有确定错误与退出码。
- 纯文本按原始 UTF-8 与 text 段发送；CQ 外观文本、多行、中文均不被转义为其他动作。
- 同请求键并发最多一次发送；超时、Ctrl+C、崩溃、持久化失败不产生隐式重发。
- 已接受结果可重复查询同键而不发信；载荷变化冲突；未知结果无法用同键重新触发。
- 帮助离线可用；业务结果仅一行 JSON；输出及默认日志不带凭据或未请求的私有正文。
- 打包白名单不带下载、QQ 数据、私人状态、实验材料或 Agent 上下文；CLI 退出不影响 QQ。
