# 原版 Framework 复用验证计划

文档编号：SPEC-003。状态：Active 验证计划。更新：2026-10-16。
依据：本轮用户要求、SPEC-001、FACT-002。实现架构仍由 RFC-0001 跟踪为 Draft。

## 本轮决定

固定 NapCat v4.18.38、提交和 DATA-001 摘要。不 fork、不改上游、不执行 QQ 或附件代码。
先评估原版包内原生入口；不可用时记录失败点，再论证自有最小加载器，不预先认定需要 fork。
FACT-003 已完成可得公开来源追溯：原版仍是条件式候选，暂不直接对日用会话运行。
技术可复用、NapCat 适用许可、QQ 协议/账号风险分别处理，不宣称任一静态结论消除另外两项。
FACT-004 确认维护者曾将原生入口作为旧 Once/OneKey 的替代，当前指南未说明其缺席原因。
Framework 与 Shell 都有反检测 Bypass 调用；本计划不能交付免下线或免封禁保证。
如果用户要求排除这种风险，当前候选不能满足验收，离线或真机功能通过也不能消除这一缺口。

## 候选装配和边界

启动协调器检查 QQ 版本、固定产物摘要和目标进程状态，调用原版原生加载入口；
该入口应保留官方启动链、捕获官方会话，传给 nativeLoader.cjs，再启动 Framework 与本地 API。
这是待验证链路，不能把原版启动器存在当作窗口与会话验收完成。
QQ 多进程本身不等于多账号会话；验收关注目标会话身份和事件一致性。
不同时执行 NCoreInitShell、不另开登录会话补偿失败、不附加现有 QQ PID。

如确需自有加载器，只负责提前接入、捕获对象、转交原版入口和观察就绪，不复制上游业务实现。
一次会话仅初始化一次；必须核对原方法/回调转发、初始化线程和官方入口的继续执行。
不凭函数返回判断成功，需观察实际登录、会话初始化及 API 状态。

候选状态：discovered → verified → launching → session-wait → api-ready；失败进入 failed，
断线进入 unavailable，不默认切账号、盲重启或重复发信。退出 CLI 不自动结束桌面 QQ。
热卸载、断线重连和异常恢复尚无保证，不以终止桌面 QQ 作为兜底。

API 只回环监听、开启鉴权，Agent 仅经白名单适配层调用；不透传任意原始 API，
不提供退出、重启、登录、更新或插件安装。WebUI 单独管理，不作为 Agent 工具暴露。
包与运行配置分离，保留附件原始字节和目录依赖；运行状态不写入仓库或日志回显。
验证前固定配置、排除待安装更新，不自动替换已核验包。如原版无法满足控制边界，记录失败，不静默放宽。

## 阶段验收

| 阶段 | 工作与完成依据 | 当前状态 |
|---|---|---|
| A 固定静态基线 | 版本/许可、ZIP、实际入口、摘要和生命周期观察；DATA-001、CHECK-002 | 本轮完成有限范围核对 |
| B 授权与原生契约 | 适用授权、原生实现来源/维护性、宿主与对象/回调契约 | 公开分发历史调查完成；生成链、支持矩阵与授权未解决，不启动真实 QQ |
| C 离线契约 | 在适用授权下，以合成对象检查一次初始化、时序、错误和失败状态 | 未实现；模拟不能证明真实会话 |
| D 只读真机实验 | 明确运行机制和用户授权后，验证窗口、目标会话、API、焦点和恢复 | 未执行 |
| E 有界发信/事件 | 明确目标和内容，验证人工/API 并行、单次发送和异常结果核对 | 未执行 |

A 不包含全部三方许可或原生可复现构建。B 无法收敛时，不把原版集成列为可交付。
当前缺口的处理顺序：整理上游待确认问题 → 建立离线契约和预检定义 → 在条件明确后另行安排受控实验。
待确认问题为原生源码/构建提交、特定 QQ 版本范围、该入口的维护状态、线程与初始化/重连回调契约。
未经明确发送授权不联系作者；不把待确认问题的整理当成已经取得答复。
QQ 支持证据按原版实测、下游报告、其他模式验证和未知分类；不因版本较新或 Shell 已修复就默认兼容。
D 前重新确认 QQ 版本、退出条件和恢复步骤；公共上下文不记录安装目录、账号或聊天记录。
本轮不复制私人凭据、不登录新会话、不终止 QQ、不发送消息。

本轮不 fork。必要修改先登记固定版本下的最小失败、维护成本和许可影响，再另议上游修复或 fork。
CLI 语言、命令契约、打包和安装脚本留待路径收敛，不因版本载体提前选型。
