# 指定群历史边界只读实验

文档编号：CHECK-009。状态：Bounded pagination boundary verified。更新：2026-10-17。
依据：用户指定群历史查询授权，现有实验实例见 CHECK-005。无发送授权或发送操作。

先检查实例在线、自身账号与实验配置匹配；仅调用自身状态及 get_group_msg_history。
批量分别使用 count=100、50、20，固定 disable_get_url=true、parse_mult_msg=false、quick_reply=false，不调用标记已读或媒体下载接口。
初始批次取最近记录，再以已返回消息 ID 作为 message_seq 游标；分别核对 reverse_order 的分页行为。
每批记录数量、时间范围、唯一消息计数和停止原因，不输出或保存群聊正文、成员或媒体链接。
目标及消息标识仅存忽略目录；查询范围只限用户指定群。

API 返回条数可能少于 count；未继续推进不自动解释为群创建以来全部历史已取完。
本次不进入 CLI 实现或群聊支持验收，M1 至 M4 进度不变。

## 实际结果

- 实验账号在线且与现有实验配置匹配，所有历史请求仅指定用户授权群。
- 首次最近批次返回 31 条；reverse_order=false 的后续查询未推进最早时间。
- reverse_order=true 配合已返回消息 ID 作为游标，可连续向前查询，取得早于本次 NapCat 启动的记录。
- 较大批次出现请求超时，延长等待仍有超时；减少到 20 条后成功越过该位置，不能把超时误判为历史结束。
- 共 16 次成功历史应答，按消息 ID 去重取得 811 条；这不是群的总消息数，也不证明没有遗漏。
- 最终一次小批量已不再推进，再以同一最早游标独立复核：请求 20 条，返回 1 条已有记录，新增 0 条。
- 由此确认本次账号/实例/接口的反向分页可达边界；具体起止时间、游标和目标只保存在忽略运行摘要中。
- 未保留正文、成员资料或媒体 URL；没有发送、撤回、标记已读、下载媒体或修改 QQ/NapCat 配置的请求。

结论：该接口可以实际取得启动之前的群历史，并可沿游标继续向前；至少在本次受限条件下能够确定一个稳定边界。
没有对照 QQ 窗口可见的最早日期、群创建日期、其他设备或其他账号，因此不能把该边界声明为 QQ 全部存储记录的起点。
边界后没有继续高频重试；超时的客户端请求是否在 QQ 内部完全取消未核验，不宣称由断开连接撤销后台处理。
只读探针已退出，无后续自动查询安排。此次实验不增加 CLI 群聊或分页功能，当前实现仍停在 M0。
