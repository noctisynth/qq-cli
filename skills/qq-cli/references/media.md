# Retrieve an attachment

Read the selected message metadata first. Use only a returned `mediaRef` with `media download MEDIA_REF --output FILE` when the task needs the attachment contents.
Do not fetch raw message URLs, pass API credentials to a media host, read arbitrary backend paths, or open/execute a downloaded attachment automatically. A media reference can expire independently of the message.
If a reference is stale, explicitly re-read that message or a bounded history range to relocate it. Failure does not prove the original attachment never existed.
Check `downloadable` before downloading; it permits a scoped download attempt and does not guarantee that remote content remains available. Image downloads resolve the source from the same fresh message element even when history omits URLs. The CLI alone handles audited HTTPS sources with certificate checks and no API credentials, proxy, redirects or automatic retry. `MEDIA_BINDING_UNVERIFIED` means no reliable source could be established; do not substitute another file or fetch its raw URL. `MEDIA_BYTES_UNAVAILABLE` requires inspecting the managed capability with `doctor`; repeating the same download cannot enable it. Follow the diagnostic next action for the selected instance.
`media prune` cleans tool-owned cache according to its policy; it preserves authenticated persistent sources used by `emoji add` and does not clear QQ's history or media directories. Do not delete QQ data to resolve a CLI error.

Record (voice) segments also expose scoped media references. `media download MEDIA_REF --output FILE` keeps the original encoding; `--format mp3` explicitly converts audio. Supported formats are original, mp3, amr, wma, m4a, spx, ogg, wav and flac; conversion requires upstream support. The returned byte count/hash describe the actual saved bytes. Format conversion is only for record attachments. Do not play the file automatically.

For a requested transcription, use `message transcribe MESSAGE_REF --request-id KEY`. This actively triggers QQ speech recognition and needs read/send permission for the source conversation. It verifies a record segment in the original message and sends one task. Only a nonempty returned text proves a result; `unknown` cannot distinguish processing, failed recognition or unavailable text. Keep the same key and inspect `request get KEY`; do not automatically retry with a new key. Text is returned only on the first successful call and never saved in request records; a cached success has `textAvailable:false`. Do not transcribe other messages automatically.
