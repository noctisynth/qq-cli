# NapCat 能力扩展与直接 API 调用

文档编号：RFC-0009。状态：Accepted，按TASK-007分切片实施。更新：2026-10-29。
关联：SPEC-001、SPEC-004、SPEC-009、PLAN-001、DESIGN-002、TASK-001、TASK-002、TASK-007、RFC-0002、RFC-0004、RFC-0006。

## 问题与接受依据

用户2026-10-27要求：上一轮接口差距审计中，除“语音、识别与 AI”组外，其余功能均为必要目标，按RFC→Spec→TODO进入工程上下文；同时希望提供裸接口调用，避免领域命令缺失限制Agent。同日补充将语音获取get_record、语音转文字fetch_ptt_text也纳入必要范围，其余8项暂缓。
本RFC依据该明确指令接受范围扩展与直接调用方向，替代RFC-0002、SPEC-004、PLAN-001中排除raw action及群管理的旧边界。真实操作仍依具体账号、目标和内容授权，不因设计更新获得会话实验授权。

审计基线为qq-cli 0.1.0提交cb6070071a1f6d43aab3cc7fc71edc2db7d2f4d7与NapCat v4.18.38提交bbd0d2aca3d470c20b33b1d4f95123335633bf26。178个唯一基础注册action中16个有生产调用、2个只有枚举声明、160个无调用。注册不证明上游实现完整或真实可用；接口数量不是产品完成度。
固定公开来源及逐项必要范围移入SPEC-009，不依赖忽略目录里的研究报告。可变main在审计时ActionName一致，仅作当日观察，不替代固定基线。

## 目标与范围

1. 保留原16个已接入action；新增154个必要缺口，合计170个基线action纳入覆盖矩阵。语音获取get_record及语音转文字fetch_ptt_text新增为R18必要能力，其余暂缓8项逐名见SPEC-009。
2. 账号资料、好友与群管理、消息互动/转发/已读、公告/精华/待办、收藏表情、文件目录/传输/相册、空间频道、凭据/底层工具及运行控制都是必要能力，不降为可选增强。
3. 领域命令提供稳定任务语义、引用、验证和结构化输出；直接API调用作为同时必要的补充。裸调用可先交付独立切片，但不能替代领域能力、非语音格式/事件补齐和完整验收。
   语音读取/获取/受控下载及显式转文字另按R18补齐领域任务；不因此扩大到语音发送、OCR或AI语音生成。
4. 不因CLI尚无专用命令而拒绝合法公开OneBot action；上游未来新增action可经直接调用使用，不要求先发布CLI白名单更新。已固定版本/兼容门禁继续约束所选实例，而非放宽到任意版本。
5. QQ主题/皮肤/聊天背景和建群在本基线未发现公开action，不虚构接口；若未来上游公开，可经直接调用接入。暂不修改或fork NapCat、不调用未公开QQ内部ABI。

## 方案比较与决定

仅补领域白名单会持续滞后；仅提供通用HTTP客户端则丢失实例与账号归属、写请求恢复等已有保障。选择“领域任务 + 受检直接调用”双入口，复用现有选择、签名运行权威、实际身份和总预算。
直接调用是访问现有NapCat实例的协议适配，不接收任意URL、端口、令牌或WebUI路径，不成为通用网络代理。
建议公开入口为api list、api describe ACTION、api call ACTION；流式能力另作明确的api stream协议切片。精确接口、预算和验收见SPEC-009。

直接调用使用动态action值，而不为每个action新增Rust枚举变体。语法验证隔离action与URL路径；未知action默认按写/未知副作用管理，不能用get_前缀推定只读。已知目录记录效应、目标、权限、敏感性、响应模式和参数Schema来源；目录用于发现与策略，不作为可调用名称白名单。
原生参数和上游结果保真，CLI类型化包装携带scope、action、结果状态与限制。仅直接调用的params/result允许明确的任意JSON协议边界，派生Schema如实表示动态值；不修改其它领域DTO。此项是RFC-0006“不能直接透传公共数据”的具名例外，不恢复全局Value桥。

## 写入、作用域和恢复

复用原实例/账号/Job/端点校验及现有read/send/mediaDownload/targets策略。只读必须来自固定的效应定义；未知action保守按写入处理，不能由调用者随意声明read绕过意图。
写入及未知效应调用须request-id，副作用前持久记录action、规范化参数摘要和账号作用域；与领域消息及启动请求共用键冲突检查。同键异参拒绝，unknown不自动重发。
dry-run只校验/展示计划，不连接QQ或产生写意图。直接调用不自动重试、不自动追随后端URL或打开文件，不把上传文件解释成无副作用步骤，不把retcode=0推断成消息送达或传输完成。
已知跨领域相同副作用应复用操作计划与指纹；不能用不同入口绕过同键检查，也不声称防止用户以新键重复操作。
目录不可证明目标范围且本地targets受限时，明确拒绝无法核对的调用；默认无目标限制时不因未知action阻塞。该限制须输出可理解原因，不能猜测参数中嵌套的目标。
bot_exit、set_restart、clean_cache、send_packet与凭据导出仍在必要范围；保留效应和所有权检查，不自动接管被上游改变的进程或恢复失效运行记录。生命周期调用后的断连可能为unknown，不能要求“后置API仍在线”才记录该可能副作用。

## 敏感内容与协议模式

凭据类接口的显式结果可返回给调用Agent；不自动访问、汇总或广播。原始正文、凭据、附件路径和返回结果不进入普通日志、公共证据或意图持久记录；请求恢复返回元数据，不重新读取秘密或伪造原始结果。
原始JSON结果只在api入口保真，明确为不可信上游数据。所有已知目录的内容来自固定源码/Schema审阅；真实能力、上游占位及兼容别名分别记录，不能以路由注册当验收。
普通JSON调用先落地。双向流式、闪传与在线文件另按固定上游协议补齐会话/分块/完成/取消，不以JSON入口能发出请求就勾选完成；流式线格式须在实现前由源代码证据冻结。

## 验收与实施顺序

先冻结SPEC-009与TASK-007矩阵，再实现直接JSON调用、目录/Schema/Skill/离线回执，随后分领域补功能、格式、事件与流式传输。依赖允许调整，不以首个切片作为完整交付。
验证涵盖未知action无需改CLI、语法注入、后缀效应归一化、参数/响应保真、身份变化/端点冲突拒绝、并发键/崩溃/未知结果、敏感不落盘和受限目标。涉及真实账号的验证另取得具体操作授权。
离线目录/详情已有CHECK-138，普通JSON直接调用与持久回执已有CHECK-139；领域能力、逐接口Schema、流式及真实验证仍按TASK-007完成，不以通用入口或阶段提交推定上游完整可用。
