# CLI 语义、职责与调用成本

文档编号：RFC-0004。状态：Accepted，按用户澄清修订，尚未实现。更新：2026-10-18。
依据：用户明确不应过度收敛，应按语义/职责拆分；关联 SPEC-004、PLAN-001、RFC-0002、RFC-0003、TASK-002。

## 原则

命令数量少不是目标。不同领域对象和不同任务即使共享后端，也应有可理解的独立入口。
减少的是重复配置、无意义前置调用、冗余参数和输出，不通过扩大隐式查询范围或模式开关合并所有操作。
接口一致性服务于语义，不要求所有任务使用同一个动词。保留合理默认值、精简输出、引用推导及按需 schema/skill。
本修订替代此前强制合并联系人/群详情、回复和文件导出的决定；CHECK-012 区分早先观察与此次修订，按最新职责为准。

## 资源与任务边界

| 命令族 | 职责 | 不承担的职责 |
|---|---|---|
| contact list/get | 好友发现、关系和用户资料 | 不以最近聊天代替好友发现 |
| group list/get/members | 所属群、群资料和成员 | 不以会话详情代替群对象资料，不管理成员 |
| conversation list/get | 最近聊天、会话标识和可用聊天元数据 | 不因 --query 隐式切换为全量好友/群搜索，不创建会话或标记已读 |
| message history/search | JSON 消息读取、查询范围与游标 | 不因 --output 参数进入文件任务 |
| message export | 文件导出、NDJSON、私有检查点、续写、覆盖保护 | 不把 stdout 当完整正文副本，不声称全量归档 |
| message send | 发起新消息，显式 --conversation | 不作为带 --reply-to 的另一回复入口 |
| message reply <message-ref> | 引用回复，从消息推导会话及实例 | 不重复填写目标，不绕过账号/防重检查 |
| status / doctor | 当前状态 / 原因诊断 | 不要求先后调用才能执行业务 |

contact/group list --query 在各自对象范围过滤，conversation list --query 始终 scope=recent。
各列表直接给可用标识，同名返回候选；已知目标或消息引用可直接执行，不强制先查资料。
conversation get 只给上游可观察的会话元数据，未提供则缺失，不推断聊天条数/已读或对象资料。

send/reply 共用文本/提及/媒体校验、请求键和状态机，但业务操作类型不同；不保留 send --reply-to 别名。
export 共用 history/search 查询引擎，使用 --conversation、时间范围、可选 --query、--output；
--resume 从文件检查点恢复，不要求重复参数。每次有预算，不能默认无限扫描或覆盖文件。
list/get 统一基本资源读取，export/reply 等任务语义保留。转发展开仍为 message get --expand，媒体元数据随消息返回，
与显式 media download/prune 职责分明，无需为保持对称新增媒体检查入口。
event watch 用单数资源，napcat 安装/实例拆分不变，schema/skill/request 保留 list/get。

## 调用成本与准确性

不新增 profile/managed/external/绑定配置。唯一候选实例自动选，多候选 --instance，实际身份变化明确失败。
schema/skill/doctor/dry-run 都按需，不是每次业务前置。错误只给必要下一步；正常输出不附长帮助。
limit/timeout/cursor 表达结果数量/总截止/续传，内部批次和扫描预算不要求 Agent 调整。
默认普通查询 limit=20、导出=1000、事件=100，硬预算见 PLAN-001。
普通满页是成功而非部分失败；中断未完成页才退出码7，范围/后端终点与全量归档区分。
紧凑包装仍保留实际身份、作用域、unknown、gap、覆盖范围和安全重试信息，不以省 token 牺牲准确性。

消息 send/reply 和 start --new 都使用 request-id；后者不能只靠进程锁防串行重试多开。
用户状态域内请求键唯一并记录操作类型，同键操作类型/载荷冲突拒绝；request get 不要求重复类别，unknown 不盲目执行。
普通 start/安装/状态不额外要求键；--dry-run 不写入/上传/占用请求键。

## 验证与影响

### 导出文件原子恢复

export 的 NDJSON 使用带 type 的记录：message 行含归一化消息，最后一行 checkpoint 含签名元数据引用。
检查点与正文在一次原子文件替换中提交，避免正文追加成功但旁置游标落盘失败导致重复；普通新导出不得覆盖既有文件。
--resume 先验证正文 SHA-256、记录数、输出路径和检查点作用域，再恢复查询；修改、截断、跨状态目录或旧运行代次明确失败。
每次仍受查询预算和 limit 约束，累计文件硬上限64MiB；stdout只有文件/计数/覆盖摘要。
同目录导出使用工具保留的无正文锁文件协调独立进程；不自动删除用户文件或恢复不明来源临时文件。

Rust 命令/输出迁移和部分读取/写入内核已有 CHECK-013 合成证据；完整任务与共享机制仍在 TASK-002，设计不计业务完成。
验证联系人/群/最近会话过滤范围不互换，reply 推导目标，export 文件恢复/覆盖和只读查询无文件副作用。
覆盖普通分页成功、未知结果、防重复创建、作用域冲突及精简错误/输出；两个 Agent 宿主再做真实任务闭环。
当前持续原创开发与离线检查，不声称已测得 token 降幅，不改后端、不执行真实会话、不暂存或提交。
