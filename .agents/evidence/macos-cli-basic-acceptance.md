# macOS 正式 CLI 基础读取与生命周期验收

文档编号：CHECK-133。日期：2026-10-26。状态：基础启动、限定读取与停止/重启通过；完整平台验收未完成。
关联：RFC-0008、SPEC-008、TASK-006；早期装配与运行记录见 CHECK-129/131/132。

## 固定范围

- QQ：官网 DMG 7.0.2-53644；NapCat Framework：v4.18.41。固定资产摘要和来源见 CHECK-072、FACT-005。
- 宿主：Apple Silicon 原生 arm64、macOS 27.0；不据此推定最低系统版本或 Intel 支持。
- 修复提交：ecdad69。验证程序使用未改动的 main.rs、Cargo 优化库和相应依赖构建，独立保留原可执行文件；部署的适配源码与该提交逐字节相同。
- 用户授权专用副本的启动、读取、停止和重启，并分别确认首次和重启后的窗口登录。权限只开放读取；未发送消息、调用媒体/事件操作或接管普通 QQ。
- 原始配置、账号结果、日志、诊断程序和上游产物均留本地忽略目录。本记录不含账号、聊天、凭据、设备标识或本机路径。

## 失败定位与修复

此前启动只返回 AUTH_REQUIRED，随后接口不监听；不能据此认定窗口正常或只需等待登录。
一次私有诊断构建在入口中捕获 Unexpected adapter path kind，位置为 application.asar 的文件类型检查；窗口观察为空。
独立物理文件观察仍为单链接普通文件。Electron 普通 fs 的 ASAR 虚拟目录行为导致该检查中止。

正式修复通过 original-fs 审计物理路径，原 QQ 入口仍用正常 require 加载 ASAR 成员；不放宽目录、链接或多链接拒绝规则。
生成宿主回归先失败再通过；26 项 Node 适配、20 项准备/部署/装配、4 项兼容性测试及 Clippy、格式、diff 检查通过。
诊断构建已通过自身原 CLI 认证停止；后续真实验收使用无诊断插桩的正式代码。

## 实测结果

| 操作 | 结果与范围 |
|---|---|
| 新建与待登录观察 | 固定安装准备、专用副本部署及派发完成；status 通过原控制通道返回 waiting_qrcode，QQ 启动日志开始生成 |
| 首次登录 | 用户确认窗口完成登录；status 返回 ready、online=true，实际账号作用域与登记一致 |
| contact list | limit=5、timeout=15，成功返回 5 项；未保存到公开上下文 |
| conversation list | limit=5、timeout=15，成功返回 5 项最近会话；不扩大为全量会话或历史验收 |
| 就绪 start | 不带试运行开关，返回 reused=true、ready；生成本次精确组合的兼容记录 |
| doctor | compatibility=supported、canStart=true、api=ready；仅适用于本记录的组合与已测范围 |
| 显式 stop | 成功返回 stopped；原进程已退出，实例与安装引用保持 |
| 显式 restart | 从已停止实例调用，不带试运行开关；实例 ID 和安装保持，产生新运行，控制接口恢复 waiting_qrcode |
| 重启后登录 | 需要再次扫码；用户确认登录后，status 返回 ready、online=true，账号与重启前相同 |
| 重启后复查 | 再次各成功读取 5 项联系人和最近会话；就绪 start 复用成功，doctor 再次为 supported、canStart=true、api=ready |

## 限制

- 这是正式 CLI 的基础可用闭环，取代早期记录中基础 GUI/登录/限定读取尚未取得正例的状态；不扩大 CHECK-129/131/132 当次实验的结论。
- 重启需要用户再次登录；未证明自动保留登录态、新运行继承全部 QQ 缓存/历史或完整数据迁移。
- 未验收其它领域接口、发送/回复/上传、媒体、WS、切号/断网、多实例、跨版本维护、长期稳定及完整故障矩阵。
- 未验收不同 CLI 签名的 Keychain 升级恢复、Windows 原生回归、托管 CI 或线上分发；本地提交不代表发布。
- 系统/软件变化回到 unknown、原进程/输入/账号变化不误签的完整真实矩阵仍保留在 TASK-006，不因本次正向链路通过而整体勾选。
