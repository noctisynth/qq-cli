# 双实验账号并行登录

文档编号：CHECK-047。状态：两个不同账号正常登录/并行复用/选择通过。更新：2026-10-20。
关联：SPEC-004、PLAN-001、RFC-0003、TASK-002、CHECK-042、CHECK-046。基线da02b62，用户本轮明确授权两个新实验实例、分别使用不同账号，随后许可仅两账号间合成文字及测试撤回。

以固定v4.18.38和两个不同稳定请求键顺序调用公开start --new --request-id KEY --timeout 120；每次返回AUTH_REQUIRED后只查询原实例，不更换键重开。官方QQ数据可能共享，先确认第一个实际账号并提示关闭自动登录，用户确认后才开第二个，由用户登录另一账号。两次status最终确认不同账号且同固定38在线，账号来自OneBot受检观察，不从启动参数或二维码预设。

两个实例分别selected start返回ready/reused:true；随后不指定实例的status返回INSTANCE_AMBIGUOUS，候选为两份旧未确认记录及两份新ready记录，没有任意挑选。原注册表中run、HTTP、WS、凭据键均不同而安装ID相同；两条API均经过原签名Job/服务连接核对。未通过复制凭据、接管旧QQ或终止他组解决冲突。

验收脚本最初误要求plain processId各异，该字段实际均null，断言失败；原权威在签名运行日志及受检socket/Job，此脚本假设不作为产品缺陷，不写入伪造PID或放宽生产校验。私人真实身份/端点/创建请求及输出只留忽略目录，公开证据只记录方法与界限。

本阶段未发送/撤回测试消息或读取聊天，未验证同账号冲突、所有扫码/密码/2FA/离线恢复及长期并行稳定性。仅正常双账号登录/复用通过；接着开发并验收事件恢复，再核对帮助/Schema/Skill。纯Agent记录无独立changeset；README用户说明使用patch:chore。
