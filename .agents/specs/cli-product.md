# 面向 coding agent 的 CLI 产品契约

文档编号：SPEC-004。状态：Active，持续开发，核心模块有离线证据。更新：2026-10-19。
依据：用户 Rust、完整工具、Agent 自动处理及易用/准确/减少 token 要求；关联 SPEC-001、PLAN-001、RFC-0002、RFC-0003、RFC-0004、TASK-002。

许可执行策略（2026-10-19，FACT-002）：独立原创CLI与外部API协议实现不等同复制上游代码；自动下载/运行涉及上游复制/使用条款，不能据下载可用推定无限授权。适用范围未知只作提示，不返回LICENSE_UNCONFIRMED、不要求作者证明或确认参数、不参与技术canStart。固定摘要、完整性、精确兼容和归属检查继续生效。捆绑/镜像/修改/商业用途单列发布审计，不因本次实现视为已许可。

## 产品要求

质量前置要求：按用户最新指令先完成RFC-0005/TASK-003的职责封装、应用/生命周期边界及维护性整改，再继续新增业务。目录和文件数量不代表模块化；须保持既有公开行为、原生隔离与验证纪律，不用根层别名或通用容器掩盖耦合。

登录观察协议候选见CHECK-016：固定WebUI管理鉴权与QQ身份分离，仅允许auth/login和CheckLoginStatus；2FA/拒绝不重试，不自行签发凭据。控制ready不得提升账号ready，输出仅固定阶段/布尔提示，丢弃二维码URL/原始错误/未知阶段正文。实现应先有纯协议测试，再接原签名预登录归属及同一受检HTTP通道，不向不受信端点发送管理秘密；目前未接公开控制调用，不勾选完整登录恢复。

创建请求查询设计：request get同时覆盖消息写意图和启动创建，不联网、不探测进程、不修改日志或补建签名密钥。创建记录只返回requestId、operation:napcat.start、持久outcome、原instance/run、登记阶段及定向下一步，不把dispatched或登记ready解释为当前在线，不填账号作用域。n1/s1目标不一致、损坏签名或显式--instance冲突拒绝；历史实例缺失/换run仍保留原请求身份。消息与启动共用请求键语义：在同一状态锁内，已被另一类操作占用的键返回REQUEST_CONFLICT；既有双类冲突不猜测选择。无记录/消息查询不访问签名凭据，启动查询只读取原密钥。

默认启动接合设计：普通start的零实例判定必须在startup操作锁内重读注册表，不能根据锁外空快照直接创建。创建前保存独立d1签名的随机内部请求键（不含账号），中断沿用原键；唯一准备态实例只有与该键n1计划的instance/run一致才恢复，多候选仍要求--instance。唯一待登录实例返回账号为空的检查点，不再次调度；starting/未知只查询，不重放。旧d1对应的registered实例被移除时不自动复活，remove实现须明确处理默认选择记录；缺失/损坏记录不能猜键。精确兼容仍先行（许可只作信息，不作运行阻断），缺安装自动准备和完整登录/注销恢复不因此视为完成。

显式新建编排按启动操作锁→状态锁的固定顺序执行，启动操作锁覆盖同键认领、运行材料准备、意图/原生调度与预登录保留；普通读取不取得启动操作锁。预留对象的初始端口须在进入后续状态事务前释放，调度阶段重新取得计划租约。已有starting/login_required/ready结果不重新准备或调度；未知意图不重放。仅预登录控制归属/t1/j1保留成功才登记login_required；这不等于账号已在线，真实未知兼容仍禁止加载。

预登录检查点返回AUTH_REQUIRED及instanceId、state:login_required、account:null、reused和原请求键，nextAction定向status --instance；不以预登录结果填入账号作用域。未知启动结果同样必须指向已认领实例，不能让多实例Agent猜测。复用ready仍需严格运行记录/版本/实际在线身份验证，不由start确认账号变化。

端口交接须同时保留计划HTTP/事件/控制三个本地监听句柄到原生创建前；任一端口不可绑定则释放本次已取得句柄并在分配Job/创建进程前拒绝，不轮换端口。实例预留与调度共用端口租约实现；释放到原版实际listen仍非原子，也不保证排除其他程序的特殊套接字复用，后续固定端点/归属守卫不可省略。

CHECK-015的固定源码/发布包仅为预登录调用顺序和直接监听构造的静态依据，不升级为实际QQ同进程或兼容supported。WebUI可能异步失败或在端口冲突后漂移；CLI仍以签名端点、实际进程/Job观测及明确失败结果为准，不扩大发现范围。

启动生命周期须在CLI释放最后本地Job句柄前建立可验证的长期保留，不以Job成员仍存在推定命名空间可恢复，也不把加载器存活等同QQ登录。若使用预登录控制监听保留候选，控制端点/QQ映像必须创建前签名，零字节归属通过后保留并登记完整进程身份；后续API绑定须同一完整身份，缺旧保留日志不得重复复制。该候选的真实Framework登录前监听与控制/API同进程条件尚未验证，不因此开放未知组合启动或认定完整恢复已完成。

显式新建的稳定请求键先认领唯一实例/run与三个本地端口，再登记preparing；账号/进程均不预设，不生成秘密或运行材料。创建认领n1先于注册表，注册成功后记录registered；同键复用原实例，registered实例已注销则INSTANCE_REMOVED，不复活。崩溃仅恢复同一reserved计划，原端口不可用就拒绝，不偷偷更换端口/ID。保留端口的本地句柄随预留对象关闭，实际启动前必须释放；释放/崩溃后的端口竞争仍需归属检查，不能承诺跨进程永久独占。创建日志属于签名权威，丢原密钥不补建。

status可对starting/login_required确认登录：无运行记录或缺启动前签名的发现输入时只输出未验证状态，不访问计划端点。有发现输入而未绑定时，只允许向日志固定端点发起一次最多2秒且受总截止限制的零字节连接，验证精确服务PID/完整映像/同Job及原连接后，先t1保留再j1绑定；不得发认证或API、扫端口、枚举接管进程或猜测映像。已绑定时只走严格受管通道，核对固定版本、实际账号与online；同一事务比较完整实例和安装快照后才登记身份，在线转ready，离线仍为login_required。账号变化按显式status返回account_changed，不迁移旧引用；快照/版本冲突不得覆盖状态。此能力不创建进程或处理二维码，首次真实原版发现兼容仍未验收。

完整调度输入以版本化摘要绑定：精确兼容键、运行Plan、原版程序/三参数/工作目录、过滤后的环境及预登录配置摘要。输入复核、运行材料只读复核和参数/环境构造须在同一状态事务内完成；原生创建前再次计算并匹配已保留Target的实例/run/安装/摘要，不符不得分配Job或创建进程。仅持久化摘要，不输出或登记秘密/命令/环境原文；该机制不替代最终受检文件加载绑定和真实启动验收。

启动前已准备运行材料须在调用者同一状态事务内只读复核，限prepared/starting且未绑定账号/进程；签名r1认领、run/安装/端点、整组秘密与独立API凭据、目录标记及全部预登录配置必须一致。缺失材料不自动恢复、补密钥或修复配置；运行后可写目录不可套用本准备态检查。该检查不替代安装/兼容/实际加载及监听归属门禁。

启动输入快照只可在现有生命周期事务中重新核对后交给后续操作；复核版本/安装ID/摘要/目录、QQ实际可执行路径和完整兼容键，任一变化或当前证据拒绝均不调用后续操作。状态锁不阻止外部程序改写文件，不可将本约束解释为受检文件已经由原版加载；最终加载绑定和实际启动仍须独立验收。

新建启动前检查须要求唯一完整版本安装及固定摘要、受检产物、最多16个QQ安装候选和唯一有效安装，最后评估精确Framework兼容键。候选超限、任一输入无法核对或多安装均拒绝，不试启动寻找可用组合。该检查只产生私有输入快照，不创建运行材料/意图，不访问账号API，不作为可跨时间复用的启动许可；实际调度仍须生命周期锁及受检文件绑定。

start复用已就绪实例时仍须验证签名运行记录、固定版本及实际在线账号，返回instanceId/reused与账号作用域；不得只看登记ready。请求版本不一致返回INSTANCE_VERSION_CONFLICT，不隐式更新；账号变化返回ACCOUNT_CHANGED，不由start确认改绑。--new不得进入复用路径；新建/零实例仍须通过完整技术启动门禁，不将复用验收计为新建完成。

安装来源契约：固定版本目录核对先于来源打开、下载和凭据初始化；命中已验证安装时不得重新访问来源。固定HTTPS发布地址最多3次显式跳转，仅接受GitHub及release-assets.githubusercontent.com默认HTTPS端口，不携带认证、使用代理或自动重试；URL最长8192字符，禁止凭据/片段。整包长度、摘要和解包预算继续生效。未确认许可只作来源/诊断信息，不参与安装或启动判定；当前真实下载仍未验收，见CHECK-013。

完整交付全部确定范围、可靠性、指引和验收，不能以部分功能或开发快照替代；不表示所有 QQ API、零缺陷或账号安全。
PLAN-001 为公共命令/模型/预算/错误契约，TASK-002 登记差距。

覆盖离线 schema/skill、NapCat 环境/固定安装/多实例、版本兼容证据、联系人/群/会话发现、
私聊/群读取、分页/时间/范围搜索/导出、文本/回复/提及/图片/文件发送、转发读取、
媒体下载/自有缓存、事件及缺口、请求记录与 Codex/OpenCode 闭环。

## 简化 UX

不公开 profile、managed/external 或预设账号绑定/改绑，外部接入不纳入必需范围。
零实例时在授权范围内自动准备，单候选自动选择，多候选返回 INSTANCE_AMBIGUOUS，--instance 精确选择；
消息引用/游标作用域优先，不能按焦点或最近活跃猜实例。
新实例无需账号，未登录 account=null；登录后输出实际身份。变化返回 ACCOUNT_CHANGED，旧作用域不可复用。
身份核对与去重是内部准确性要求，不让 Agent 维护配置或填冗余字段。
默认只返回任务结果与简短作用域，详细 schema/诊断按需读取。

napcat install/installations/uninstall 管理本地安装；start/instances/stop/restart 管理实例，
remove 注销停止实例，update/rollback 明确切换实例版本。每个对象有不同 ID，一份安装可供多实例使用。
start 默认复用，--new --request-id 明确另开并防串行重试多开；stop 不卸载，uninstall 不关闭 QQ，被运行或停止实例引用的安装不得删除。
remove 不删除 QQ 数据或防重记录，卸载只删除工具拥有的无引用产物，注册与文件变更防并发竞争。
产物先核对私有快照的固定长度/摘要再解包，限制压缩/展开大小、成员数/深度并拒绝不安全路径和链接；机制与预算见 RFC-0003。
安装使用签名所有权清单、确定ID和状态锁；卸载保护已停止实例的引用，持久移除日志后只删除已验证清单成员，中断重试保留未知文件、QQ数据和请求记录。

## 语义与职责要求

以 RFC-0004、PLAN-001 为目标命令面，解析/帮助已迁移，完整领域 schema 和业务仍在实施。
status 汇总实际账号/就绪，doctor 诊断环境/版本/能力，登录恢复使用 napcat start，不另设 self/auth/capabilities 等重复入口。
doctor只读采集，区分安装元数据、精确Framework兼容证据和所选实例API；API成功或静态/Shell报告不能提升为完整兼容。canStart仅受检前置条件，真实元组与实际启动绑定仍须验收。
contact list/get 负责好友和资料，group list/get/members 负责群及成员，conversation list/get 负责最近聊天和会话信息。
conversation list --query 始终仅过滤最近会话，contact/group 过滤各自对象范围，不隐式跨域；已知目标无需先发现/查询详情。
message send 面向新消息，reply <message-ref> 面向引用回复并推导目标，共享防重但不互为别名。
message history/search 只返回查询 JSON；export 独立负责文件、可选检索、检查点/--resume、覆盖保护，stdout 仅文件摘要。
导出为带 type 的 NDJSON，message 行与末尾签名 checkpoint 行在一次原子替换中提交；续写先核对正文摘要与作用域，累计上限64MiB。
schema/skill/request 统一 get，event 单数；转发展开仍 get --expand，消息自带媒体元数据，download 才取内容。
公共数量/截止/续传统一 limit/timeout/cursor，不暴露取页批次/页数/投影 DSL。
普通满页成功不代表完整历史；中断部分页才返回退出码 7，不制造正常分页错误。
成功 JSON 省略空字段/重复 command/日常关联号，保留作用域/范围；失败保留必要恢复信息，不让 Agent 猜测。
无需每次先 schema/doctor/dry-run，真实命令内部检查；不以命令最少为目标；按语义分工，通过默认值和按需发现降低调用成本。

## 边界与验收

使用原版 Framework，不改 NapCat、不 fork、不开发加载器，不用 UI 自动化替代 API，不打包上游。
Windows、NapCat v4.18.38 为证据基线，其他支持需来源和验证；unknown 兼容不能冒充 supported 或默认加载。
不提供 raw action、群管理、自动回复或执行聊天指令；身份发现不自动授予业务权限。
CLI 退出不关 QQ，不自动终止外部 QQ、挤掉账号或重启活跃窗口。
登录挑战/系统授权明确阻塞，安装选择、预检、目录隔离及启动控制面尚待机制验证。
按 PLAN-001 整体验收，包括安装卸载/实例引用、并发、身份切换、防重、历史边界、媒体、事件及两个宿主。
无真实回归证据即未验收，许可和分发问题仍需解决。

## 当前状态与授权

登录观察实现顺序：先在napcat/control中封装固定WebUI鉴权和状态协议，以受限Route枚举和独立Backend承接受检传输。管理token只产生内存hash，Credential不实现Debug/Serialize；固定阶段和四个布尔提示可输出，不返回账号、原始错误或二维码URL。HTTP200仍须校验code=0，2FA、拒绝、异常不得重试或继续状态查询；单次观察最多鉴权/状态各一次，共用截止。协议内核成功不是公开CLI或真实QQ登录恢复验收。
受检控制HTTP复用transport内私有owned_wire，OneBot与WebUI各自负责协议包装；不复制HTTP解析器。每次POST连接先对原socket核对Pinned/Job/TCP归属，再发送body和可选Bearer，响应后复核owner/Job/总截止；控制响应上限64KiB且受配置更低预算约束。控制路由只能由固定枚举提供，认证请求不发送账号API token或Bearer，状态请求仅用服务端Credential；不接受任意路由、URL、query token或跨端点重定向。
运行后控制恢复分两项只读能力：j1原prelogin绑定须与当前实例/run/安装摘要、discovery映像/控制端点及已有API进程一致，重开原Job/Pinned并验证已有t1，不扫描/连接/补留句柄或写记录。r1恢复只读原签名准备日志、最终目录marker及原vault秘密，核对当前实例和安装快照、版本/三端口/摘要/秘密引用；不对运行后logs/cache/tmp作空目录要求，不读日志或任意后端路径，不从可变配置获取秘密，不修复/重建缺失材料。两项固定控制端点必须相等才可向受检HTTP提供管理token；此阶段不提升账号状态。
公开status在starting/login_required且受检账号服务尚未绑定/监听时，仅尝试已有签名控制绑定。无控制绑定保持原未验证状态，不猜端点；已有绑定损坏、缺秘密、2FA/鉴权拒绝等返回明确错误，不降级为成功。有效观察在未验证data内增加loginObservation（固定phase及isLogin/isOffline/qrLoginAccepted/coreReady），account保持null、identityVerified保持false且无账号scope，不改登记。发请求前及返回前核对完整实例/安装快照，原状态锁不跨网络等待。control ready不触发本次额外API重试，下次status只有经受检OneBot核对真实在线身份才可提升。schema get status严格覆盖未验证与已识别账号的分支。
已绑定账号端点仍在待登录阶段时，OneBot的连接拒绝BACKEND_NOT_LISTENING（尚未发送请求）或缺实际身份AUTH_REQUIRED也可走同一只读控制观察；不重放OneBot请求。一般BACKEND_TRANSPORT含坏HTTP帧，不作为降级条件；版本、账号变化、鉴权拒绝、协议或归属错误不得被控制面掩盖，ready实例的错误亦不降级为待登录提示。
status读取顺序先取版本并立即核对，再取身份和在线状态；未知/不匹配版本即停止，不因身份也未就绪而误入控制提示，也不额外重取版本。底层inspect保留调用方版本守卫接口，普通消息用例不改变已有身份门禁。
