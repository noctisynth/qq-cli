# 安装、运行身份与生命周期技术方案

文档编号：SPEC-006。状态：Active，共享约束与 Windows 机制；macOS 对应机制见 SPEC-008。更新：2026-10-27。
需求：RFC-0003。公共行为：PLAN-001。平台扩展：SPEC-008。验收：TASK-002/TASK-006。

以下记录共享设计约束及 Windows 的 n1/r1/j1/p1/g1/v1 协议。macOS 的 n2/l2/r2/j2/p2/g2/v2、专用 QQ 来源和隔离启动由 SPEC-008 定义；本文的 Windows Job、FILETIME、凭据命名空间及三参数 ABI 不直接移用于 macOS。历史试验过程见各 CHECK。

## 输入与精确兼容

本地启动实证（2026-10-20）：显式生命周期操作可对已ready的原受管实例收集本地Framework启动证据。需固定产物完整性/当前精确QQ与主机元组、原r1秘密及计划、重建完整输入摘要与原j1分派摘要吻合、原服务PID/映像/Job可重开且在线账号前后一致；API成功或用户声称不单独授予兼容。兼容索引用原签名权威，限定64条、按完整Key指纹读取，本地记录不代表上游支持/安全或其它版本；原安装CWD的旧记录仅作准确摘要匹配迁移。doctor只读加载既有证据，不创建记录，未知/不支持及冲突规则保留。见CHECK-042。

启动工作目录（2026-10-20）：原版三参数仍为绝对QQ/加载器/入口；原生子进程CWD必须为同run已验证的私有运行目录，不能是安装包或QQ安装目录及其上下级。CWD沿输入摘要及最终同锁复核绑定。不得通过忽略未知安装文件解决运行日志污染，已有未知运行文件保留，未恢复完整性前不停止后尝试重启。实例验收见CHECK-041。

真实启动修复：打包宿主的目录虚拟化可能改变目录创建前后的凭据命名空间。新安装先建立私有状态根；已有状态沿同一逻辑根的原父目录解析别名读取原权威，双签名权威冲突拒绝，不补建密钥。QQ入口可在ASAR内；只读校验有界索引和内嵌成员范围，指纹绑定完整归档，链接/外部解包/越界拒绝。

首次组合试验使用napcat start --new --request-id KEY --verify-compatibility显式发起。仅放行输入完整、架构受支持且缺少精确历史证据的组合；已知不支持、证据冲突、产物变更等仍拒绝。试验权限绑定本次完整输入并沿锁内复核，不持久化为supported，不适用于自动启动；显式update --verify-compatibility允许对固定已安装目标进行同样的完整输入绑定试验（不得跳过不支持/冲突/完整性门禁），未给参数时仍要求精确实证。update支持总截止--timeout；登录前控制可用也不证明消息/账号兼容。

完整原生参数和环境编码预检应先于持久派发意图，支持Windows标准带括号变量名。规范路径用于文件验证和身份绑定，向上游位置参数及PATH/SYSTEMROOT/WINDIR/TEMP/TMP/NAPCAT_WORKDIR输出普通本地盘符路径，保持同一已验证文件/目录，不透传UNC或注入覆盖变量。

启动输入快照只可在现有生命周期事务中重新核对后交给后续操作；复核版本/安装ID/摘要/目录、QQ实际可执行路径和完整兼容键，任一变化或当前证据拒绝均不调用后续操作。状态锁不阻止外部程序改写文件，不可将本约束解释为受检文件已经由原版加载；最终加载绑定和实际启动仍须独立验收。

新建启动前检查须要求唯一完整版本安装及固定摘要、受检产物、最多16个QQ安装候选和唯一有效安装，最后评估精确Framework兼容键。候选超限、任一输入无法核对或多安装均拒绝，不试启动寻找可用组合。该检查只产生私有输入快照，不创建运行材料/意图，不访问账号API，不作为可跨时间复用的启动许可；实际调度仍须生命周期锁及受检文件绑定。

start复用已就绪实例时仍须验证签名运行记录、固定版本及实际在线账号，返回instanceId/reused与账号作用域；不得只看登记ready。请求版本不一致返回INSTANCE_VERSION_CONFLICT，不隐式更新；账号变化返回ACCOUNT_CHANGED，不由start确认改绑。--new不得进入复用路径；新建/零实例仍须通过完整技术启动门禁，不将复用验收计为新建完成。

版本维护补充：rollback亦支持总截止--timeout；共享身份/API版本解析显式接纳固定v4.18.37、v4.18.38及v4.18.41，仍先要求运行版本与登记精确相等；各平台可启动目录及精确证据独立检查，macOS见SPEC-008，未来目录版本不得自动获得协议支持。CHECK-025中两版napcat.cjs摘要相同，CHECK-043补真实身份/版本维护。

## 安装来源与事务

安装来源契约：固定版本目录核对先于来源打开、下载和凭据初始化；命中已验证安装时不得重新访问来源。固定HTTPS发布地址最多3次显式跳转，仅接受GitHub及release-assets.githubusercontent.com默认HTTPS端口，不携带认证、使用代理或自动重试；URL最长8192字符，禁止凭据/片段。整包长度、摘要和解包预算继续生效。未确认许可只作来源/诊断信息，不参与安装或启动判定，来源事实见 FACT-002。

## 创建、配置和调度

创建请求查询设计：request get同时覆盖消息写意图和启动创建，不联网、不探测进程、不修改日志或补建签名密钥。创建记录只返回requestId、operation:napcat.start、持久outcome、原instance/run、登记阶段及定向下一步，不把dispatched或登记ready解释为当前在线，不填账号作用域。n1/s1目标不一致、损坏签名或显式--instance冲突拒绝；历史实例缺失/换run仍保留原请求身份。消息与启动共用请求键语义：在同一状态锁内，已被另一类操作占用的键返回REQUEST_CONFLICT；既有双类冲突不猜测选择。无记录/消息查询不访问签名凭据，启动查询只读取原密钥。

默认启动接合设计：普通start的零实例判定必须在startup操作锁内重读注册表，不能根据锁外空快照直接创建。创建前保存独立d1签名的随机内部请求键（不含账号），中断沿用原键；唯一准备态实例只有与该键n1计划的instance/run一致才恢复，多候选仍要求--instance。唯一待登录实例返回账号为空的检查点，不再次调度；starting/未知只查询，不重放。旧d1对应的registered实例被移除时不自动复活，remove实现须明确处理默认选择记录；缺失/损坏记录不能猜键。精确兼容仍先行（许可只作信息，不作运行阻断）；缺安装时要求显式 install。

显式新建编排按启动操作锁→状态锁的固定顺序执行，启动操作锁覆盖同键认领、运行材料准备、意图/原生调度与预登录保留；普通读取不取得启动操作锁。预留对象的初始端口须在进入后续状态事务前释放，调度阶段重新取得计划租约。已有starting/login_required/ready结果不重新准备或调度；未知意图不重放。仅预登录控制归属/t1/j1保留成功才登记login_required；这不等于账号已在线，真实未知兼容仍禁止加载。

预登录检查点返回AUTH_REQUIRED及instanceId、state:login_required、account:null、reused和原请求键，nextAction定向status --instance；不以预登录结果填入账号作用域。未知启动结果同样必须指向已认领实例，不能让多实例Agent猜测。复用ready仍需严格运行记录/版本/实际在线身份验证，不由start确认账号变化。

端口交接须同时保留计划HTTP/事件/控制三个本地监听句柄到原生创建前；任一端口不可绑定则释放本次已取得句柄并在分配Job/创建进程前拒绝，不轮换端口。实例预留与调度共用端口租约实现；释放到原版实际listen仍非原子，也不保证排除其他程序的特殊套接字复用，后续固定端点/归属守卫不可省略。

显式新建的稳定请求键先认领唯一实例/run与三个本地端口，再登记preparing；账号/进程均不预设，不生成秘密或运行材料。创建认领n1先于注册表，注册成功后记录registered；同键复用原实例，registered实例已注销，或存在原移除意图时均为INSTANCE_REMOVED；reserved日志也不能在移除后复活登记。崩溃仅恢复同一reserved计划，原端口不可用就拒绝，不偷偷更换端口/ID。保留端口的本地句柄随预留对象关闭，实际启动前必须释放；释放/崩溃后的端口竞争仍需归属检查，不能承诺跨进程永久独占。创建日志属于签名权威，丢原密钥不补建。

完整调度输入以版本化摘要绑定：精确兼容键、运行Plan、原版程序/三参数/工作目录、过滤后的环境及预登录配置摘要。输入复核、运行材料只读复核和参数/环境构造须在同一状态事务内完成；原生创建前再次计算并匹配已保留Target的实例/run/安装/摘要，不符不得分配Job或创建进程。仅持久化摘要，不输出或登记秘密/命令/环境原文；该机制不替代最终受检文件加载绑定和真实启动验收。

启动前已准备运行材料须在调用者同一状态事务内只读复核，限prepared/starting且未绑定账号/进程；签名r1认领、run/安装/端点、整组秘密与独立API凭据、目录标记及全部预登录配置必须一致。缺失材料不自动恢复、补密钥或修复配置；运行后可写目录不可套用本准备态检查。该检查不替代安装/兼容/实际加载及监听归属门禁。

托管配置模板只面向固定审核版本与将要创建的私有实例，不覆盖任何已有QQ/NapCat配置。预登录生成通用onebot11.json、webui.json及napcat.json，不生成预设账号文件；HTTP/WS/管理面使用三个不同的非特权IPv4回环端口。业务API与事件共享专用随机密钥，管理令牌与JWT签名密钥分别独立生成，不放入普通注册表或默认输出；JSON配置由私有目录/ACL和所有权事务承载。模板启用array消息、自发事件及文件字节能力，禁用反向上报/插件/CORS/调试和文件日志，不改变未核实的Hook/Bypass参数。管理端口自动回退不能当已发现，发出管理凭据前必须核对实际监听所有权；上游日志不直接继承到CLI。

运行配置准备事务仅接受同一登记实例/run、preparing或prepared阶段、未记录进程/账号且端点一致的计划。先持久签名所有权日志，再向一个受保护凭据条目保存整组秘密，业务原始token条目可从该组恢复；未知既存条目不得接管。配置进入日志预先认领的固定暂存目录，已有成员仅可为准确预期内容的子集，缺失成员可补齐，额外/修改/链接拒绝且不覆盖。完整目录在Windows以不覆盖语义发布后再提交prepared阶段；重试复用同一秘密。内部r1所有权引用不向公共命令开放。此处不授权进程启动：生命周期必须先持久starting意图再spawn，准备函数拒绝后续运行阶段，不能用目录存在推断进程未启动。

准备中的未完成暂存文件仅允许追加与原预期一致的缺失后缀，不能改写任何已存在字节；完整已发布文件必须准确匹配。准备态不能进入业务身份探测或事件连接，status只报告未验证的登记阶段和account=null，不把计划端口当真实API。已有写意图的离线结果查证仍按原契约保留，不为读取旧结果发新请求。

控制监听仅 SERVICE_NOT_READY 可在命令总截止内轮询，最多1200次、每次等待250ms；归属冲突或保留未知不得重试或重启。

## 控制观察、身份及受检传输

登录观察协议的静态依据见CHECK-016：固定WebUI管理鉴权与QQ身份分离，仅允许auth/login和CheckLoginStatus；2FA/拒绝不重试，不自行签发凭据。控制ready不得提升账号ready，输出仅固定阶段/布尔提示，丢弃二维码URL/原始错误/未知阶段正文。实现应先有纯协议测试，再接原签名预登录归属及同一受检HTTP通道，不向不受信端点发送管理秘密；实施与验收状态见 TASK-002。

CHECK-015的固定源码/发布包仅为预登录调用顺序和直接监听构造的静态依据，不升级为实际QQ同进程或兼容supported。WebUI可能异步失败或在端口冲突后漂移；CLI仍以签名端点、实际进程/Job观测及明确失败结果为准，不扩大发现范围。

启动生命周期须在CLI释放最后本地Job句柄前建立可验证的长期保留，不以Job成员仍存在推定命名空间可恢复，也不把加载器存活等同QQ登录。若使用预登录控制监听保留候选，控制端点/QQ映像必须创建前签名，零字节归属通过后保留并登记完整进程身份；后续API绑定须同一完整身份，缺旧保留日志不得重复复制。该条件必须在具体平台组合验证，不自动开放未知组合。

status可对starting/login_required确认登录：无运行记录或缺启动前签名的发现输入时只输出未验证状态，不访问计划端点。有发现输入而未绑定时，只允许向日志固定端点发起一次最多2秒且受总截止限制的零字节连接，验证精确服务PID/完整映像/同Job及原连接后，先t1保留再j1绑定；不得发认证或API、扫端口、枚举接管进程或猜测映像。已绑定时只走严格受管通道，核对固定版本、实际账号与online；同一事务比较完整实例和安装快照后才登记身份，在线转ready，离线仍为login_required。账号变化按显式status返回account_changed，不迁移旧引用；快照/版本冲突不得覆盖状态。此能力不创建进程或处理二维码，具体组合的验收范围见 TASK-002。

登录观察实现顺序：先在napcat/control中封装固定WebUI鉴权和状态协议，以受限Route枚举和独立Backend承接受检传输。管理token只产生内存hash，Credential不实现Debug/Serialize；固定阶段和四个布尔提示可输出，不返回账号、原始错误或二维码URL。HTTP200仍须校验code=0，2FA、拒绝、异常不得重试或继续状态查询；单次观察最多鉴权/状态各一次，共用截止。协议内核成功不是公开CLI或真实QQ登录恢复验收。
受检控制HTTP复用transport内私有owned_wire，OneBot与WebUI各自负责协议包装；不复制HTTP解析器。每次POST连接先对原socket核对Pinned/Job/TCP归属，再发送body和可选Bearer，响应后复核owner/Job/总截止；控制响应上限64KiB且受配置更低预算约束。控制路由只能由固定枚举提供，认证请求不发送账号API token或Bearer，状态请求仅用服务端Credential；不接受任意路由、URL、query token或跨端点重定向。
运行后控制恢复分两项只读能力：j1原prelogin绑定须与当前实例/run/安装摘要、discovery映像/控制端点及已有API进程一致，重开原Job/Pinned并验证已有t1，不扫描/连接/补留句柄或写记录。r1恢复只读原签名准备日志、最终目录marker及原vault秘密，核对当前实例和安装快照、版本/三端口/摘要/秘密引用；不对运行后logs/cache/tmp作空目录要求，不读日志或任意后端路径，不从可变配置获取秘密，不修复/重建缺失材料。两项固定控制端点必须相等才可向受检HTTP提供管理token；此阶段不提升账号状态。
公开status在starting/login_required且受检账号服务尚未绑定/监听时，仅尝试已有签名控制绑定。无控制绑定保持原未验证状态，不猜端点；已有绑定损坏、缺秘密、2FA/鉴权拒绝等返回明确错误，不降级为成功。有效观察在未验证data内增加loginObservation（固定phase及isLogin/isOffline/qrLoginAccepted/coreReady），account保持null、identityVerified保持false且无账号scope，不改登记。发请求前及返回前核对完整实例/安装快照，原状态锁不跨网络等待。control ready不触发本次额外API重试，下次status只有经受检OneBot核对真实在线身份才可提升。schema get status严格覆盖未验证与已识别账号的分支。
已绑定账号端点仍在待登录阶段时，OneBot的连接拒绝BACKEND_NOT_LISTENING（尚未发送请求）或缺实际身份AUTH_REQUIRED也可走同一只读控制观察；不重放OneBot请求。一般BACKEND_TRANSPORT含坏HTTP帧，不作为降级条件；版本、账号变化、鉴权拒绝、协议或归属错误不得被控制面掩盖，ready实例的错误亦不降级为待登录提示。
status读取顺序先取版本并立即核对，再取身份和在线状态；未知/不匹配版本即停止，不因身份也未就绪而误入控制提示，也不额外重取版本。底层inspect保留调用方版本守卫接口，普通消息用例不改变已有身份门禁。
OneBot身份响应必须为对象，缺user_id/null/空串/零可表示尚无身份（AUTH_REQUIRED）；非空非法标识或错误类型属于BACKEND_PROTOCOL，不能被控制观察掩盖。有效账号仍须通过规范十进制校验。
无登记实例且未指定--instance时，status离线返回state:not_started、account:null、identityVerified:false；属于未验证schema分支，不初始化状态/凭据、不探测或启动QQ。显式选择不存在的实例仍返回INSTANCE_NOT_FOUND。

显式napcat stop结束所选实例的私有Job进程树，包括共用的官方QQ窗口；不用于普通业务故障的自动修复，不声称QQ登出、优雅退出或草稿保存。不按名称/全局PID终止、不停止其他实例，不卸载安装或清理QQ、运行、消息/未知写入记录。查询/传输仍仅有QUERY，停止另取QUERY|TERMINATE且不继承的原Job句柄，必须先有原签名j1与当前instance/run/安装匹配；不借停止接管无记录的现有QQ。
生命周期操作共用startup.lock再取短state.lock，状态锁不跨原生等待；先签名停止意图和登记stopping，再至多调用一次原生终止并有界等待Job为空。只有持原句柄观察到空组并先保存签名完成凭据后，才能登记stopped；重复已完成操作复用凭据，不要求请求键。未知/失败不伪报停止，保留记录及定向诊断，后续显式stop须重核同一不可变目标。若原Job已无法重开且无完成证明，不能把失去名称当作进程全部退出。
preparing/prepared取消仅在无s1运行认领和j1调度、账号/进程字段均为空时登记停止，不调用原生终止；存在任一调度痕迹不得按未运行处理。注销、重启与更新共用同一生命周期锁，并按相应操作管理运行代次，remove须保留旧数据与防重记录，不能凭plain stopped状态绕过停止证明。
公开stop在访问凭据前按登记选择实例，零/多候选或不存在的显式选择直接失败，不调用OneBot或控制API。成功仅输出instanceId、state=stopped、reused，不广告已验证账号作用域；reused表示复用原完成证明。并发相同目标停止可接受仅阶段变化，仍须完整实例其余字段和安装匹配；不得借此容忍换run、账号或端点。
停止等待后确认登记时，须逐字段重核进入stopping时的完整实例及安装登记快照，包括账号/端点/凭据键/进程字段与安装版本/位置。完成证明可以已持久化；快照变化或确认失败仍报告停止结果未知并保留当前登记，不覆盖并发变化、不请求再次终止。
复用已有完成证明时，登记确认写入失败同样报告STOP_OUTCOME_UNKNOWN，保留证明供同目标后续查证，不伪装成功或发起新的原生终止。
停止unknown错误仅定位原instanceId，不将旧stopping意图阶段输出为当前登记观察；并发变更后的实际状态由status/doctor另行核对。
remove只接受stopped且有同一instance/run/安装摘要的签名停止完成证明；先持久注销意图，再退役精确匹配该实例/run的默认创建活动指针，最后原子移除登记并保存完成记录。原签名默认记录、创建记录、运行资料、凭据和请求均保留；其他实例的默认指针不动。注销中断后仅从原签名意图恢复，不把不存在的任意ID当成功。重复注销不要求安装仍在，不能复活原创建请求。
默认活动指针存在但原签名创建记录缺失/损坏时，拒绝继续注销并保留登记、指针和原注销意图；不把无法核对解释为与当前实例无关。
凭据原生互斥等待上限1000ms，句柄非继承、权限最小化，析构绑定取得锁的线程。原生凭据调用在当前Windows会话内的qq-cli线程/进程间协调，保留条目身份、持久化策略和既有状态/生命周期锁，不自动重写丢失密钥、不重试凭据或业务副作用。协调不替代状态事务，不能仅由互斥代码存在推定恢复可靠；原并发与独立原生回归须保留。
已停止实例再次启动必须保留instanceId，仅在原停止完成证明和当前安装/实例登记复核后建立新run；新run清空未确认账号和旧进程字段，取得新端点计划和独立凭据键，保留旧运行材料/秘密/请求及创建记录。候选计划的签名认领先于新创建记录及登记替换，中断恢复只能复用原计划，不能另配run或端口，也不能重建已注销实例。
新run沿用既有创建/准备/一次调度门禁；准备计划本身不是兼容许可或进程启动。签名运行来源保留原创建根身份，默认指针可仅凭已核对来源证明识别同一稳定实例的后继run，不能只凭instanceId删除其他运行的默认指针。
停止后的普通start使用所选实例原安装版本，兼容输入核对先于新代次及凭据准备；Windows同一生命周期锁内接合新run、r1准备、s1/j1一次调度和预登录保留；macOS以p2/g2/n2认证后继，再凭原内部键续接r2及s1/j2，锁释放/重取规则见SPEC-008。后继preparing/prepared从原签名来源/内部键恢复，不使用旧默认创建键重建；starting/unknown已有意图不得重放。ready/login_required复用仍须后续身份/受检控制核对，start不等于已登录。
凭据协调不得带来全局unsafe许可、句柄继承、无限等待或跨线程释放；超时/abandoned/不可访问时明确报凭据不可用，不绕过协调直接调用原生存储。底层异常根因与完整故障矩阵另由证据记录，不承诺零故障。

普通业务、状态API探测、事件及doctor的API层统一从可信签名运行记录恢复服务身份，核对所选run/安装摘要/端点及完整进程/Job；缺失或损坏不得回退到普通HTTP/WS，非标准凭据键也不构成例外。已有完全匹配的幂等回执仍能离线返回，不以当前进程/凭据不可用授权重发。独立低层协议测试不替代该CLI门禁；合成服务成功不证明原版启动、兼容或真实账号安全。

## Windows 原生机制与维护日志

维护约束：需在停止副作用前持久绑定源run/完整安装快照、目标安装和update/rollback动作，保留目标引用，覆盖p1完成到g1认领之前的退出；不能让普通start误将未认领的停止源当成应恢复旧版本。回滚须区分“正在恢复原回滚”与“明确切回上一安装”，不能仅看当前rollbackInstallation反复切换。采用独立签名维护意图并按固定索引恢复，复用p1/g1/n1，不引入公开模式或任意信任参数；目标安装缺失时不得先停止原运行。

维护意图：v1签名记录源快照/源安装/目标安装及update或rollback，按源实例/run固定索引；Registry可选maintenanceIntents仅保存当前实例的签名引用，先索引后标记，再允许p1。普通start对待维护源返回原操作指引，卸载保护其目标。g1可选maintenanceReference继续绑定原签名，n1/新run登记与当前标记退役同一次Registry写入，索引/标记缺失或冲突不猜测补建。只有索引已写、源完整快照尚未改变的准备失败可恢复标记；注销明确退役该实例当前标记但保留历史。覆盖范围见 TASK-002。

回滚编排：目标解析在短状态事务中检查完整当前快照、v1原动作及g1当代动作/回滚安装；原rollback源快照重复调用复用已记录目标，回滚准备快照推进后仍恢复同代，普通重启不继承旧动作。先解析目标以构造受检上下文，生命周期锁内再解析并核对，之后复用版本维护用例且v1记录Rollback。无历史/动作冲突不推断，未知不重放；旧准备快照若后继已停止则拒绝，不再生成一代。已完成后新选择的run上的rollback为新维护，不承诺无请求键的新调用能识别人类意图。目标须先显式安装；恢复覆盖范围见 TASK-002。

已运行版本不符返回冲突，不借 start 偷偷更新；维护更新及回滚另有授权/窗口，不保证回滚 QQ 自身数据。

受检WS：复用现有Connection解析/握手/帧与预算，在TCP创建后、任何Upgrade/Bearer写入前通过Job/Pinned验证原socket，之后不重连。握手成功后再复核进程/Job；失败关闭该连接，不输出HTTP错误正文。普通与受检入口共用一个connect实现，不复制事件解析。该入口不替代HTTP/WS账号关联、订阅恢复或托管客户端选择，具体覆盖见 TASK-002。

受检HTTP：不把归属核对后丢弃socket再交reqwest重连。使用已在依赖图内固定版本的hyper HTTP/1连接级接口与Tokio适配同一TcpStream，认证字段仅在Job/Pinned/TCP绑定成功后装入请求并发送；无连接池、代理、跳转或重发。固定Action路径、显式Host/JSON/Connection-close、请求4MiB、响应按普通4MiB或媒体专用预算、头部32KiB/64项；严格响应编码与HTTP状态、分帧交标准库处理，业务仍复用OneBot领域解析。总截止覆盖序列化/连接/核对/发送/读取，使用绝对timeout_at与发送前检查，不重起算；异步连接任务在完成/失败/截止时取消，不留下等待keepalive的任务。不编写自定义HTTP分帧器。

连接归属：凭据只能在已建立且仍持有的同一TcpStream上发送；GetExtendedTcpTable按该流的本地/远端精确四元组反向匹配服务器ESTABLISHED行，并与可信Pinned/Job成员匹配，前后复核身份与第二次连接快照。只检查监听者再另行连接不足以防端口重用。IPv4/IPv6分别按SDK结构解析，观测上限2MiB/8192行、最多3次缓冲区增长，重复/缺失/非目标PID拒绝；系统表其他行立即丢弃，不持久或输出非目标连接信息。不读取应用数据、不探测QQ API。该内核仅证明观测时当前连接归属，不保证恶意成员随后不转移socket；完整HTTP/WS须复用验证后的流，不再新连接或发凭据前隐式探测。

后代句柄保留：仅对可信run Job内已持句柄验证的进程，重新取得DUP_HANDLE/QUERY_LIMITED_INFORMATION/SYNCHRONIZE句柄并核对完整PID/创建值/映像，再以同一目标句柄IsProcessInJob前后复核。DuplicateHandle仅向该目标复制非继承QUERY权限的Job句柄，不加载代码、不读写目标内存、不终止、不复制其他句柄。目标退出由OS关闭副本；远端句柄数值不是本地HANDLE，不在本地CloseHandle，也不按陈旧数值远程回收。复制前须持久一次性意图，复制后失败为unknown禁止自动重复，由 t1 签名保留事务承载。该方案先用原创父子进程对照验证，不能自动推定真实QQ/安全检查兼容。

原子创建：native::job 内使用PROC_THREAD_ATTRIBUTE_JOB_LIST在CreateProcessW阶段入Job，同时HANDLE_LIST只继承一枚QUERY权限的Job副本及一枚显式NUL读写设备句柄，不继承父进程管道/其他句柄。Job副本保留根进程存活期间的名称。显式Unicode环境块、CRT兼容参数编码、绝对应用名和工作目录、无窗口辅助控制台及NUL标准流；原生测试发现传入空标准句柄在程序运行后不再保持空值，故不依赖该推断。不经shell，不使用先spawn再assign，不引入挂起后等待恢复的孤儿窗口。成功后从原始返回进程句柄构建Pinned，不重新按PID猜测；CreateProcess成功后的任何验证失败均是未知结果。调用前仍须私有日志登记Job ID与启动意图并完成全部真实操作授权/兼容门禁。根进程继承副本不能证明原版加载器退出后实际QQ子树仍保留句柄，后者须通过 t1 保留事务及固定组合验证，不能据根句柄推定全部跨 CLI 恢复完成。

命名Job：按run生成256位随机Local命名，创建时拒绝既存对象，显式owner/SYSTEM DACL及不可继承句柄，禁止kill-on-close和breakaway。原生测试纠正初始推断：成员存活但最后句柄关闭后，名称已不能重开，因此仅保存Job名不能完成跨CLI归属；使用根进程受控继承与已验证后代的 t1 句柄保留，不默认添加全局常驻服务。后续只从可信私有记录以QUERY权限重开；名称形状本身不是归属证明。成员列表单次有界到256项，与持句柄进程观测前后复核结合，不全局枚举同名QQ。当前winsafe无Job接口，已审查匿名安全封装不足以重开；使用固定Microsoft windows 0.62.2绑定（MIT OR Apache-2.0），Windows 仅 native::job 与 native::credential_lock 边界允许有安全注释的原生 unsafe，物理实现位于 native/windows；macOS 独立边界见 SPEC-008，结构约束见 DESIGN-002。创建/只读重开/成员及句柄关闭语义的历史证据见CHECK-013；不得将启动后再assign的竞态当作生产归属保证。

进程观测：只对调用方给出的PID使用不可继承、QUERY_LIMITED_INFORMATION|SYNCHRONIZE句柄，在同一存活句柄上读取PID、FILETIME创建时间及Win32映像路径，零等待前后复核退出。保留句柄期间及重新打开后均按完整身份比对，避免只以PID或STILL_ACTIVE退出码推定存活。路径观测不证明已加载文件摘要、父子归属或实际监听；禁止通过枚举同名QQ自动接管。原生接口只观测，不提供终止/注入权限。winsafe固定版本映像路径缓冲区有限，查询失败须拒绝，不退回脚本猜测路径。
AUTH_REQUIRED 保留检查点；不接收密码或绕过扫码/系统授权。启动/登录焦点影响单独测量。
