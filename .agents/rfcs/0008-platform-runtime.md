# Apple Silicon macOS 支持需求

文档编号：RFC-0008。状态：Accepted。更新：2026-10-27。
技术方案：SPEC-008；事实：FACT-005；实施：TASK-006。

## 目标

在 Apple Silicon 原生 arm64 上提供与 Windows 同一命令语义的 QQ CLI，保留官方 QQ 窗口并共享其真实会话。
复用协议与领域逻辑，将平台能力隔离；不要求兼容 Intel/Rosetta，不将本轮扩展自动扩大到 Linux。

## 已确认取舍

- 不依赖 LiteLoader，不 fork 或修改 NapCat；优先原版 Framework 接入。
- 现有上游入口不足时，允许最小外部适配，职责限于装配、对象转交、真实就绪观察和路径兼容。
- 使用专用 QQ 副本本地 ad-hoc 重签名；不修改原安装，不关闭 Gatekeeper/SIP，不接管或终止无关会话。
- Shell 独立会话不能替代官方 GUI 共用会话要求。
- 不承诺 NapCat Windows 的所有扩展在 macOS 对等；明确平台限制，不用接口存在推定可用。
- CLI升级后的Keychain恢复由用户显式触发系统授权；常规Agent调用保持无交互，不复制凭据、替换签名权威或自动更改ACL。

## 验收要求

分开验证启动、GUI、实际账号一致、OneBot API、事件、媒体、生命周期、隔离与恢复。
固定 QQ/NapCat/系统/架构组合，保持原版产物可核验；新版本不能继承旧兼容结论。
进程/连接归属、凭据和停止边界不得因平台移植而降低；安装、升级、CI、分发和 Agent 指引纳入平台交付。
实现与验收状态由 TASK-006 维护；原型、正式 CLI 正常功能、故障矩阵及公开交付分别取证，单机结果不推导最低系统版本或长期稳定性。
